# 风格来源与模型整合

2026-09-19：独立 Analysis Lab 增加 `extensions.genre`，原生产 API 的风格、舞种与选歌逻辑不变。

## 数据覆盖

只读核对生产 `library_songs`：45 条；22 条音频规则结果，23 条显式人工标签，2 条舞种适配评分。旧人工记录可能没有 `method`，用 `manual_primary_style` 或候选的 `source=manual` 识别，不能当作音频分类输出。

21 类高频风格规则存在于另一个本地工作副本，当前生产服务未运行该实现。本次不合并那个副本。报告若已有 `music_features.high_frequency_styles`，风格页面仍会显示。

同步现有曲库与 NAS 后，共 208 份正式来源，207 份可用真实分轨曲线，1 份无分轨，接入与测量错误均为 0。覆盖数量是数据存在性，不是模型准确率。页面核对正式来源时先取同一曲目的最新报告，再按音频身份去重；旧版本不重复计数。

## 五条独立证据

- **模型候选**：Discogs400 冻结分类头 + 现有 EffNet 骨干，400 个原始多标签 sigmoid 分数全部保留。显示大类、前五个细分候选及 30 秒窗口候选。大类取最高子类；不做 softmax 或重新归一化。
- **音频规则**：保留原 `genre_profile` 和匹配依据。最高候选常归一为 1，因此称匹配分而不是置信概率。
- **舞种适配**：保留 `dance_style_scores` 原尺度，不与模型分数平均。缺失值明确显示未提供。
- **外部平台**：包括生产 `spotify_audio_merged` 混合结果，单独列明原始出处，不冒充独立音频模型。
- **人工标签**：原数据库标签完整保留；新增修正写到 Lab 的 `style-reviews`，不写生产数据库。每行一个标签，允许类别本身带逗号。确认或待复核、备注、时间和历史版本都保留。

模型候选暂不参与自动选歌或混音决策；仍要结合节拍、结构、人声和低频。

## 推理、缓存与版本

Jetson 复用现有 ARM CPU TensorFlow 适配环境。分类头节点为 `serving_default_model_Placeholder` → `PartitionedCall:0`；元数据来自 Essentia 官方模型库。每 30 秒独立窗口，整曲分数对所有有效特征帧取平均，避免把末尾短窗口与完整窗口等权。

EffNet 缓存按音频完整 SHA256、骨干文件 SHA256、运行后端／版本、采样范围、预处理协议生成键。乐器与风格模块共用缓存，格式验证失败则重新计算，原子落盘。模型输出与报告记录权重指纹、耗时、后端、缓存命中数及许可证。

单模块接口：`POST /api/analysis-lab/reports/{id}/modules/genre`；其他已有模块也可单独运行。每个任务先核验原曲指纹，再执行选中的模块，合并到原报告的扩展集合中，生成新报告。原始来源哈希不改变。

重新同步源数据时只继承音频身份已核验、输入兼容的扩展结果。重复段落模块还要求段落边界一致；已记录的最新失败不会被更早的成功静默替代。旧报告始终保留。

人工修正按音频身份保存，报告版本之间共享。最初未绑定音频的标注在原曲核验成功后建立身份别名；已有绑定不得改指向另一首音频。并发编辑使用版本号防止覆盖，冲突时提示重新载入。

## 对照口径

`GET /api/analysis-lab/styles/audit` 返回部署说明、覆盖情况和逐曲对照。仅对明确人工标签且能对应 Discogs 类别的曲目统计首选／前五一致数。HipHop 拼写别名显式映射，舞种 Breaking 不强行映射成音乐类型。大类人工标签只能验证大类一致性，不能证明细分类别正确；已有人工标签未经过本轮盲听复核。

模型固定词表不覆盖所有当代细分风格。未映射的人工标签单独列出；规则与模型自身分数不互相证明优劣。新的人工确认完成后可点击“更新覆盖与对照”再计算，支持导出完整 JSON。

验证证据：`outputs/style-model-validation.json`、`outputs/style-instrument-cache-validation.json`、`outputs/style-library-comparison.json`。模型用途和授权见 `THIRD_PARTY.md`。
