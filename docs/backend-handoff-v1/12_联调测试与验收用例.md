# 12 联调测试与验收用例

状态：`v1.0-draft`
主负责人：测试 / 架构师
必须评审：后端、算法、前端、RK、运维、产品

## 1. 验收目标

本文件把 01、03–11 转成可执行的交付门。P0 只有在“数据、接口、算法、设备、恢复、安全”同时通过后才算完成；单端演示成功或返回 HTTP 200 不能代替端到端验收。

## 2. 当前测试资产与缺口

仓库已有较多算法和模块测试：

- `app/tests/`：BPM/Beat/Key、Stem、鼓/Bass、pre-style、style、DJ fingerprint、transition、model validation 等；
- `modules/*/tests/`：设备 operation/reconnect、asset sync、manifest、audio runtime、transition orchestrator 等模块级合同；
- `cypher-integration/rk3588-edge/tests/`：sync worker、edge state、audio forwarding、transition API 等；
- `mobile/test/` 和 `modules/mobile-dj-control/tests/`：少量 Flutter 测试；
- 顶层 `tests/`：BPM/downbeat/stem automix 基线。

现有测试的主要缺口：

1. 多数算法/抽取模块测试没有证明当前 Jetson 生产 FastAPI、数据库与 RK 主路径已集成；
2. 缺少新全局 Track/个人关联模型的 migration 和权限测试；
3. 缺少 OpenAPI 端到端合同、token rotation、对象级授权；
4. 缺少持久 Worker 的崩溃/租约/Redis 丢消息恢复；
5. RK 配对、SQLite outbox、重启同步、operation timeout_unknown 仍需主路径测试；
6. 缺少阿里云 Gateway → Jetson → NAS 的真机 Range/签名 URL 验收；
7. 缺少手机“未连 RK 仅试听，连 RK 才能现场”的页面门控自动化。

### 3.3 三方字段评审方法（算法—后端—前端）

对每个面向用户的分析字段逐行确认：

| 问题 | 算法回答 | 后端决定 | 前端决定 |
|---|---|---|---|
| 单位/范围/null | 计算语义和不确定性 | DB 类型/DTO/schema | 格式/空态 |
| 置信度 | 校准版本、验证域 | 是否对外/降级门 | 确定或“可能”文案 |
| 版本变化 | 是否可比、需否重跑 | 新 Run/兼容投影 | 缓存失效/状态提示 |
| 错误/不可用 | 原因与可重试性 | error code/任务状态 | 用户动作 |
| RK 是否需要 | 实时执行所需最小字段 | Manifest 投影 | 准备/现场展示 |

评审结果必须反映到 04 Schema、06 DTO、07 映射和 09 Manifest，四处由合同测试检查一致。

## 7. P0 功能验收用例

### A01 注册、登录和 token rotation

前置：新邮箱、App client_id。

步骤：注册 → 调 `/me` → refresh → 用旧 refresh 再次刷新 → logout。

预期：

- 密码库中为 Argon2id；日志无密码/token；
- refresh 后旧 token 立即失效；旧 token 重放触发 family 撤销；
- access token 过期只发生一次并发 refresh；
- logout 后 refresh 不可用；
- 401/429 有稳定 error code。

### A02 对象级授权

两个用户 A/B；A 有 private playlist、pending Track、Owner device。

预期：B 猜 UUID 不能读取/修改这些对象；请求 body 填 A 的 user_id 也无效；错误不泄露对象是否存在；临时 viewer 不能发 control，controller 只能在权限/有效期内操作。

### A03 上传、去重、分析和审核

步骤：A 创建上传、上传音频、complete；重复网络请求使用同 key；B 上传同内容；分析成功；reviewer publish。

预期：

- 只有一个全局 Track/资产分析版本；A/B 各有一个 user_library_item；
- 上传字节、MIME、size、sha256 经服务端确认；
- 任务 Core→Stem→Feature→Style/Media 状态可查询；
- A 分析后立即在个人曲库看到，公共目录在 pending_review 时不可见；
- reviewer publish 后公共目录可见；审核有 audit log；
- 如果 `CATALOG_AUTO_PUBLISH=true`，同用例仅跳过 pending_review，表/API不变。

### A04 个人曲库删除

A 从个人曲库删除公共 Track。

预期：A 的活动关联消失；B/公共目录/歌单规则按各自关联保持；tracks、media_assets、NAS 文件数量不减少；重复 DELETE 返回 204；文案是“从我的曲库移除”。

### A05 未连接 RK 的手机能力

中央在线，App 未发现/连接 RK。

预期：能登录、浏览、搜索、整理曲库/歌单、上传、看分析；`preview` grant 可播放规定试听片段；不存在原曲/完整歌曲 URL；准备同步/现场按钮明确禁用；不能仅凭中央 `device.online=true` 启用现场。

### A06 歌单/草稿版本冲突

A 的两台手机同时修改同一 playlist/prepare draft。

预期：第一个成功 version+1；第二个旧 If-Match 返回 `RESOURCE_VERSION_CONFLICT` 和 current_version；服务端不丢第一项；前端拉新状态并提示/合并。

### A07 分析降级展示

使用 style `needs_review`、downbeat 低置信、某 optional adapter unavailable fixture。

预期：Core BPM/Key 可按质量展示；风格为“可能”或不显示；RK Manifest 不包含虚假 downbeat；Run partial/degraded 而不是永久 running；App 不展示内部模型错误。

### A08 管理审核与封禁

普通用户尝试 review 失败；reviewer publish/reject；admin block 已发布 Track。

预期：权限正确；每次状态变更不可覆盖审计历史；blocked 停止新 preview/asset grant/Manifest；个人删除不能达到 block/物理删效果。

## 8. 分析 Worker 验收

### W01 API 重启不丢任务

创建 Run 后立即停止 API，Worker 继续完成，重启 API 能查到状态/产物。

### W02 Worker 崩溃接管

Stem 执行中 kill -9。租约到期后另一 Worker领取；旧 Worker（模拟晚到）不能提交；最终只有一组 ready 资产。

### W03 Redis 清空

Run 在 queued，清空 Redis/重启 Redis。Dispatcher 从 PostgreSQL outbox 对账补发，任务完成。

### W04 输出非法

算法输出缺字段/NaN/asset hash 错。Stage 为 `ANALYSIS_OUTPUT_INVALID/ASSET_INTEGRITY_FAILED`，不切 Track current run，不生成 ready Manifest。

### W05 取消

在 queued/running 分别取消。queued 不开始；running 在最大确认时间终止子进程；staging 清理/保留按策略；终态 Run 再取消不改历史。

### W06 模型版本并存/回滚

同 Track 用 pipeline V1/V2 生成两个 Run；原资产不覆盖；原子切换 current；回滚后 App/Manifest 使用 V1 一致资源。

## 9. RK 配对、能力和控制验收

### R01 Owner 和临时控制

A 首次配对为 Owner；B 用新码抢占失败；A 授权 B controller 1 小时；B 控制成功、到期失败；A 撤销后在线 RK 拒绝。Owner 可有第二台 RK。

### R02 动态 Pad 能力

分别连接 8 Pad 和 4 Pad/no-loop 模拟设备。

预期：App 动态渲染；同一 8 slot preset 对 4 Pad设备在 freeze/activate 明确 422；后端不截断；固定控制数不占 slot；实体 keycode 不出现在中央合同。

### R03 operation 幂等与 timeout_unknown

发送 `talk.set(true)` O1，模拟 RK 执行但 HTTP/WS 响应丢失。App 查询 O1/快照得到 executed；同 O1 重发不再次执行；同 O1 不同 payload 返回幂等冲突。

### R04 实体键与 App 一致

实体播放/Pad键触发。App WS 收到 source=physical 的 operation/state；音频只执行一次；Jetson补传事件含相同事实；修改硬件 profile 不改中央 API。

### R05 App/WS 重连

现场中杀 App、断 WS、RK 重启三种场景。

预期：App 重连先快照再增量；旧 sequence 丢弃；gap 触发快照；RK reboot 的 boot_id 变化被识别；pending operations 不盲重放。

### R06 中央断网现场继续

Manifest/资产已 ready，切断 RK 到阿里云 30 分钟。App 局域网控制仍执行；事件入 outbox；恢复后按 sequence 全部补传且不重复。

## 10. Manifest/同步验收

### S01 公网直拉

RK 仅连接手机热点，不加入 Tailscale。通过阿里云 HTTPS 获取 Manifest/grant、Range 下载 Jetson/NAS 资产，校验成功。资产流量不经过 App 进程。

### S02 签名和目标设备

修改 Manifest 一个字段、换 target device、过期/撤销。RK 分别以 signature/authorization/expired 错误拒绝，不创建 ready cache。

### S03 断点、重启和 hash

大资产下载 60% 断网，恢复；下载中重启 RK；服务端 ETag 变化；注入 hash 错误。

预期：正确 Range resume 或安全从零重下；最终仅完整 hash 文件原子 ready；hash 错有限重试后告警；`.part` 不被 audio-engine 使用。

### S04 去重和空间

两个 Manifest 引用相同 hash；只下载一次并保持引用。构造空间不足：先淘汰允许内容，不淘汰 active/pinned；仍不足在下载前返回 `RK_STORAGE_INSUFFICIENT`。

### S05 required/optional

optional waveform 失败、required Stem 失败。前者 job partial 且按策略可开场；后者 failed，App 不启用开始现场。

### S06 手机退出

同步 accepted 后杀 App。RK 继续直拉和验证；App 重启从 RK 获得 cache_ready；中央镜像 sequence 不倒退。

## 11. 故障恢复验收

| 编号 | 注入故障 | 必须结果 |
|---|---|---|
| F01 | 阿里云 Nginx 重启 | App/RK 退避，幂等请求不重复副作用 |
| F02 | 私网隧道断开 | Gateway 503+Retry-After；不写第二数据库；恢复后正常 |
| F03 | PostgreSQL 重启 | API readiness false；Worker 不丢任务；恢复后租约/队列对账 |
| F04 | Redis 重启/清空 | DB/outbox 补发；无永久 queued |
| F05 | NAS 掉载 | 上传/分析/grant 停止；不写 mountpoint 本地目录；恢复后对账 |
| F06 | Jetson 整机重启 | DB/Redis/NAS/Worker/API 按依赖启动；Run 恢复；无 startup 重分析风暴 |
| F07 | RK 突然断电 | SQLite WAL恢复；operation/outbox/sync 状态不损坏；文件临时态安全 |
| F08 | 手机切后台/进程杀死 | RK现场继续；重启快照恢复 |
| F09 | 时钟偏移 | sequence/id 去重仍正确；时间加 quality flag |
| F10 | 磁盘到高水位 | 拒绝新工作/安全 GC/告警，不损坏 ready 资产 |

## 12. 安全验收

- 登录暴力破解/配对码枚举被限流且响应不泄露；
- 旧 refresh 重放、伪造 JWT、错误 audience device token 被拒；
- B 枚举 A 的 UUID 不能读/写；
- 上传文件名 `../`、伪 MIME、损坏音频、超限 body 被安全处理；
- Manifest 指向 `127.0.0.1`/内网恶意 URL 时 RK 拒绝；
- 篡改 asset/Manifest/signature/hash 被拒；
- Nginx access、App、Worker、RK journal、崩溃报告无 token/密码/配对码/签名 query/NAS绝对路径；
- PG/Redis 从公网和 Tailscale 非授权节点不可连；
- 9100 从热点网卡不可访问；audio socket 权限正确；
- 管理 review/block/retry/切 current run 均有审计；
- dependency/model/license/secret scan 无 P0/P1 未处置问题。

上线前应安排独立渗透/代码安全评审，尤其覆盖 pairing、对象级授权、asset grant 和上传。

## 13. 性能和稳定性

### 中央 API

- 典型 GET/写 API p95 < 500ms（不含上传/下载）；
- 100 并发读/目标并发写下 DB pool 不耗尽；
- cursor 分页稳定，无重复/漏项；
- 大 body/慢客户端不拖垮 Worker/API。

### 分析

- 对代表性短/中/最长曲目记录各阶段 p50/p95、GPU/RAM/temp/NAS IO；
- Stem 并发 1 时不 OOM；调并发必须以报告为依据；
- 24 小时混合队列无永久 running、lease 风暴、临时目录无界增长；
- 模型指标不低于当前基线/批准容差，低置信按 abstain。

### RK

- 局域网 operation accepted p95 < 80ms（目标网络）；
- 状态 WS 4–10Hz 下手机不卡顿/序列稳定；
- 音频 24 小时压力 xrun 在硬件验收阈值内；
- 同步与现场并行不引发可听 dropout；
- 断网 outbox 容量和恢复吞吐满足至少一场活动时长；
- 缓存 GC 不删除打开/active 资源。

## 14. 数据迁移验收

从当前 `Song + LibrarySong` 快照迁移：

1. 前后 Track/用户关联/歌单/分析/资产计数报告；
2. 相同 content hash 合并，只有同名不同内容不合并；
3. 所有旧 ID 有 `legacy_id_map` 或明确孤儿报告；
4. 每个迁移 asset 补 size/sha256，未校验不进 Manifest；
5. 用户删个人库不会删除全局文件；
6. 双读样本字段一致；
7. migration 中断可恢复，生产快照升级锁时在窗口内；
8. 备份恢复和应用回滚演练完成后才归档旧表。

## 16. 缺陷分级与退出标准

- Blocker：数据丢失/越权/重复现场执行/音频不可用/无法恢复；不得上线；
- P0：核心流程不可用、事件/任务永久丢、Manifest校验绕过；不得进入下一 Gate；
