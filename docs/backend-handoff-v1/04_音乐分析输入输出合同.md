# 04 音乐分析输入输出合同

状态：`v1.0-draft`
合同版本：`music-analysis-v1`
主负责人：算法
必须评审：后端

## 1. 合同目的

本文定义目标稳定合同，不代表当前代码已经满足。算法代码可以继续迭代，但不能在不升级 `schema_version` 的情况下改变字段类型、单位、枚举或语义。当前 Drum v3/v4、Pre-style v5 `measured` 枚举和 Style fail-closed 均需在冻结前修复。

后端只依赖经过 Worker 适配层验证的 artifact，不直接依赖算法内部 Python 对象，也不把整块原始 `music_features` 无筛选返回给 App 或 RK。

## 2. 阶段和依赖

| 阶段 | `stage_key` | 输入 | 主要输出 | 失败影响 |
|---|---|---|---|---|
| 核心分析 | `core` | 标准音频 | BPM、Beat、Downbeat、Key、Cue、Energy、Transition | P0 必需；失败则 Run failed |
| Stem 分离 | `stem_separation` | 标准音频 | vocals/drums/bass/other 文件与质量 | P0 对完整设备包必需；可按产品策略形成 partial |
| 特征分析 | `feature_analysis` | Core + Stem | 鼓、低频、和声、生产、预风格证据 | Stem 成功后执行；失败可 partial |
| 风格分析 | `style_analysis` | Core + Feature | 21 类高频风格候选、置信度、复核原因 | 非现场播放硬依赖；失败可 partial |
| 媒体派生 | `media_derivatives` | 原曲/分析 | preview、waveform、必要 render | Preview 是 App P0；Manifest 所需资产缺失则不可同步 |

当前仓库的实际顺序位于 `app/modules/library/background_tasks.py`，为 Core → Demucs `htdemucs` → Stem/Feature → High-frequency Style，并附加 DJ fingerprint 和可选外部元数据。目标实现保留算法顺序，但由 05 中的持久 Worker 编排。

## 3. 输入合同

Worker 调用算法 adapter 的标准输入：

```json
{
  "contract_version": "music-analysis-v1",
  "analysis_run_id": "018f0000-0000-7000-8000-000000000001",
  "track_id": "018f0000-0000-7000-8000-000000000002",
  "stage_key": "core",
  "input_asset": {
    "asset_id": "018f0000-0000-7000-8000-000000000003",
    "storage_key": "tracks/018f.../original/source.flac",
    "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
    "size_bytes": 23456789,
    "content_type": "audio/flac",
    "container": "flac",
    "codec": "flac",
    "duration_ms": 243120,
    "sample_rate_hz": 44100,
    "channels": 2
  },
  "execution": {
    "pipeline_version": "<git-sha+model-set>",
    "requested_device": "auto",
    "max_analysis_duration_seconds": 420,
    "deadline_at": "2026-08-28T11:00:00Z",
    "seed": 0
  },
  "upstream_artifacts": []
}
```

约束：

- `storage_key` 由 Worker 的受信任存储层解析；算法 CLI 不接受 App 传入任意绝对路径；
- Worker 调用前再次校验 sha256，算法输出中回显 `input_sha256`；
- 当前 Core 最多分析 420 秒，但必须上报媒体真实 `duration_ms` 和实际 `analyzed_duration_ms`；
- 输入音频必须先通过 ffprobe/等价工具探测；损坏、加密、无音轨或超限文件在算法前失败；
- 算法不得联网获取用户数据。可选外部元数据通过独立 adapter 和明确超时执行，失败不影响核心结果；
- 所有模型路径、命令和 GPU 选择来自 Worker 配置，不来自用户请求。

## 4. 所有 Artifact 的公共外壳

```json
{
  "schema_name": "core_music_analysis",
  "schema_version": "1.0.0",
  "contract_version": "music-analysis-v1",
  "analysis_run_id": "018f0000-0000-7000-8000-000000000001",
  "track_id": "018f0000-0000-7000-8000-000000000002",
  "stage_key": "core",
  "pipeline_version": "<git-sha+model-set>",
  "input_sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "generated_at": "2026-08-28T10:10:00Z",
  "status": "ready",
  "quality": {
    "overall_confidence": 0.87,
    "validation_status": "validated",
    "calibration_version": "tempo_model_validation_v1",
    "flags": []
  },
  "data": {}
}
```

公共枚举：

- `status`: `ready | degraded | unavailable`；
- `quality.validation_status`: `validated | failed_validation | provisional | candidate_only | unavailable | deprecated`；
- `semantic_level`: `measurement | derived | semantic`；
- 所有 confidence/reliability/score 范围是 `[0,1]`，未知必须用 `null`，不能用 0 伪装未知；
- 时间点统一为从音频起点计算的整数毫秒；曲线必须明确采样/窗口时间，禁止只给无坐标数组；
- 非有限浮点 `NaN/Infinity` 禁止进入 JSON。

## 5. Core Artifact：`core_music_analysis@1.0.0`

### 5.1 标准字段

| 字段 | 类型/单位 | 必需 | 语义 |
|---|---|---|---|
| `duration_ms` | int ms | 是 | 媒体真实时长 |
| `analyzed_duration_ms` | int ms | 是 | 实际参与算法的范围 |
| `tempo.bpm` | number BPM | 是 | 最终选择值 |
| `tempo.confidence` | 0..1 | 是 | 共识置信度 |
| `tempo.stability` | 0..1/null | 是 | 速度稳定度 |
| `tempo.needs_review` | boolean | 是 | 分歧或低置信度 |
| `tempo.selected_engine` | string | 是 | 最终引擎/共识策略 |
| `tempo.engine_results[]` | object[] | 是 | 各路线 bpm/confidence/error，不向普通 App 全量公开 |
| `tempo.curve[]` | `{at_ms,bpm,confidence}` | 是 | 有界采样，最多 2,000 点 |
| `beat_grid.offset_ms` | int | 否 | 首个网格偏移 |
| `beat_grid.interval_ms` | number | 否 | 均匀网格间隔 |
| `beat_grid.beats[]` | `{at_ms,confidence}` | 是 | 最多 50,000 点；超出改二进制资产 |
| `beat_grid.downbeats[]` | `{at_ms,confidence,bar_index}` | 是 | 低置信度允许空 |
| `beat_grid.time_signature` | int/null | 是 | 当前主要支持 3/4、4/4；未知 null |
| `beat_grid.needs_review` | boolean | 是 | Downbeat/Meter 需复核 |
| `key.key` | string/null | 是 | 规范调名，如 `C# minor` |
| `key.camelot` | string/null | 是 | 如 `12A` |
| `key.confidence` | 0..1 | 是 | 最终置信度 |
| `key.needs_review` | boolean | 是 | 引擎不一致 |
| `key.candidates[]` | `{key,camelot,score,engine}` | 是 | 有界候选，最多 5 个 |
| `energy.overall` | 0..1 | 是 | 全曲能量 |
| `energy.curve[]` | `{start_ms,end_ms,value}` | 是 | 窗口化能量 |
| `loudness.integrated_lufs` | number/null | 是 | 可用时输出 |
| `loudness.true_peak_dbfs` | number/null | 是 | 可用时输出 |
| `cues[]` | object[] | 是 | 技术 Cue 点 |
| `sections[]` | object[] | 是 | 段落候选 |
| `phrases[]` | object[] | 是 | 乐句/小节结构 |
| `transition_windows[]` | object[] | 是 | 可用于过渡的时间窗 |
| `groove` | object | 是 | 当前 groove 技术摘要 |
| `danceability` | object | 是 | 分数和证据，不宣称审美事实 |
| `dj_hot_cues[]` | object[] | 是 | DJ 候选 hot cue |
| `transition_recommendations[]` | object[] | 是 | 技术建议，不直接作为 RK 指令 |

### 5.3 当前算法字段映射

当前 `analyze_audio_file` 结果映射如下；Worker adapter 负责从旧平面结构转成上述结构：

- `bpm` → `tempo.bpm`
- `bpm_curve` → `tempo.curve`
- `tempo_stability` → `tempo.stability`
- `beat_points`、`beat_confidence/details` → `beat_grid.beats`
- `beat_grid_offset/interval` → `beat_grid.offset_ms/interval_ms`
- `downbeats`、`time_signature` → `beat_grid.downbeats/time_signature`
- `key/camelot_key/key_confidence/key_profile` → `key.*`
- `energy/energy_curve/loudness_profile` → `energy/loudness`
- `cue_points/section_analysis/phrase_map` → `cues/sections/phrases`
- `transition_windows/groove/dancefloor_profile/dj_hot_cues/transition_recommendations` → 同名规范结构。

旧字段不得直接永久复制到 App DTO；无法规范化的内容只进入 `raw_debug_artifact`，默认不保留或只短期保留。

## 6. Stem Artifact：`stem_analysis@1.0.0`

### 6.1 文件输出

Demucs 路线当前为 `htdemucs`，目标输出 4 个 `media_assets`：

| variant | 建议格式 | 必需 | 说明 |
|---|---|---|---|
| `vocals` | WAV/FLAC，采样率与母带一致 | 是 | 人声 |
| `drums` | WAV/FLAC | 是 | 鼓组 |
| `bass` | WAV/FLAC | 是 | 低频 |

每个资产必须有 `asset_id, size_bytes, sha256, duration_ms, sample_rate_hz, channels`。四个文件只有全部完成校验后，`has_complete_stems=true`。

## 7. Drum Artifact：目标 `drum_transcription_consensus_v4`

当前代码常量已经是 v4，仓库现有 `drum-analysis.schema.json` 仍固定 v3。正式合同必须补 v4 Schema 和兼容 fixture，不得继续让代码和 Schema 使用不同版本。

数据源是 Demucs drums stem。标准输出：

```json
{
  "schema_version": "drum_transcription_consensus_v4",
  "source_variant": "drums",
  "events": [
    {"type": "kick", "at_ms": 117, "confidence": 0.93, "engine": "adtof"}
  ],
  "counts": {"kick": 120, "snare": 60, "hihat": 330, "tom": 4, "cymbal": 12},
  "density": {},
  "patterns": [],
  "fills": [],
  "beat_alignment": {},
  "engine_routes": [],
  "confidence": 0.84,
  "quality_flags": []

```

当前验证边界必须写进 `model_evidence`：

- `kick`：validated；
- 合并 `high_percussion`：validated；

- App/RK 不能用低质量独立鼓类别触发不可逆自动控制。

顶层：

```json
{
  "version": "pre_style_evidence_v5",
  "status": "degraded",
  "music_context": {},
  "feature_groups": {
    "rhythm_grammar": {},
    "low_frequency": {},
    "percussion_timbre": {},
    "vocal_delivery": {},
    "harmony": {},
    "production": {}
  },
  "validation_summary": {},
  "analysis_modules": {},
  "confidence": {"overall": 0.72},
  "quality_flags": ["uncalibrated_semantic_features"],
  "selected_models": [],
  "model_evidence": {"status": "unavailable", "routes": {}}
}
```

公共 artifact envelope 仍使用 `schema_name/schema_version`；这里的 `version` 是 `data` 内部 Pre-style 产物版本，二者不得混用。

每个 feature 必须包含以下字段，不允许因为模型未运行而省略关键语义：

| 字段 | 类型 | 说明 |
|---|---|---|
| `canonical_name` | string | 稳定名称 |
| `availability` | available/unavailable | 能否计算 |
| `detected` | boolean/null | 判定；无法判定 null |
| `score` | number/null | 原始或规范分数 |
| `probability` | number/null | 只有校准后才允许声称概率 |
| `decision_threshold` | number/null | 原始特征判定阈值 |
| `confidence/reliability` | number/null | 置信度与可靠性 |
| `quality` | object | `measurement_confidence/source_quality/estimator_quality/calibration_status` |
| `quality_flags` | string[] | 质量标记 |
| `evidence_level` | string | 证据级别 |
| `analysis_method/sources/time_ranges/evidence` | string/array/object | 路线、来源和证据时间范围 |
| `semantic_level` | measurement/derived/semantic | 语义层级 |
| `measurement_score/technical_reliability` | number/null | 测量分数和技术可靠度 |
| `decision` | present/candidate/absent/not_detected/unknown/rejected/measured | 决策说明码；连续型验证可为 measured |
| `validation_status` | validated/failed_validation/provisional/candidate_only/unavailable/deprecated | 发布门 |
| `validation_scope` | string | 当前验证覆盖范围 |
| `calibration_version` | string | 校准版本；unavailable 也必须给出合同使用的校准版本 |
| `style_required_allowed` | boolean | 是否允许进入风格强判定 |

`feature_registry.py` 的 fail-closed 规则必须保留：未知、未校准或 unavailable 不能自动升级为 validated。当前 `feature_calibration_v1` 尚无完整校准内容，因此任何 pre-style 特征都不能笼统声称“已完成发布验证”。

低频模型当前可注明：Basic Pitch 在 isolated Bass 上 note F1 约 0.8805，音符测量可视为验证结果；进一步的语义描述仍为 provisional。

## 9. 高频风格 Artifact：`high_frequency_style_analysis_v4`

支持的稳定 style ID：

`boombap, trap, funk, breakbeat, soul_neo_soul, jazz_hiphop, afro_afrobeats, house, grime_uk_hiphop, rnb, disco, jersey_club, drill, amapiano, moombahton, dancehall, baile_funk, memphis_trap, rage, uk_garage, trap_soul`

输出：

```json
{
  "schema_version": "high_frequency_style_analysis_v4",
  "status": "needs_review",
  "review_reasons": ["primary_margin_too_small"],
  "primary_style": null,
  "primary_candidate": {"style_id": "house", "score": 0.69, "confidence": 0.61},
  "top_styles": [
    {"style_id": "house", "score": 0.69, "confidence": 0.61, "validation_status": "provisional"},

  "detected_styles": [],
  "influences": [],
  "styles": {},
  "group_scores": {},
  "model_label_evidence": [],
  "instrument_evidence": [],
  "external_tags": [],
```

## 10. Beat/Tempo 当前验证声明

仓库当前验证资料允许以下精确声明，后端不得扩大：

| 能力 | 版本/数据 | 可用声明 |
|---|---|---|
| Tempo 共识 | `tempo_model_validation_v1` / GiantSteps | accuracy1 约 0.8387，accuracy2 1.0；适用域有限 |
| Beat | `beat_model_validation_v1` / Beat This GTZAN heldout | Beat F1 约 0.8855，validated |
| Downbeat | 同上 | 原始输出不整体 validated；置信门约 0.925 时接受覆盖约 0.7241、接受集 F1 约 0.9018 |
| Meter | 同上 | 接受集 accuracy 约 0.9231；低置信必须 abstain |

这些数值是当前仓库基线，不是永恒产品承诺。每次模型/阈值更新需要新的 calibration/validation version、数据集说明和回归报告。

## 12. 错误合同

算法 adapter 抛出标准错误，不直接暴露 traceback：

| 错误码 | 可重试 | 例子 |
|---|---|---|
| `ANALYSIS_INPUT_MISSING` | 否/运维修复后 | NAS 文件不存在 |
| `ANALYSIS_INPUT_HASH_MISMATCH` | 否 | 文件被改写/损坏 |
| `ANALYSIS_UNSUPPORTED_MEDIA` | 否 | 无音轨、格式不支持 |
| `ANALYSIS_MODEL_UNAVAILABLE` | 是 | 模型路径未部署 |
| `ANALYSIS_GPU_OOM` | 是，降并发 | Demucs OOM |
| `ANALYSIS_STAGE_TIMEOUT` | 是 | 超出阶段 deadline |
| `ANALYSIS_OUTPUT_INVALID` | 否，代码缺陷 | JSON Schema 校验失败 |
| `ANALYSIS_EXTERNAL_ADAPTER_FAILED` | 依场景 | 可选元数据失败，通常降级 |
| `ANALYSIS_CANCELED` | 否 | 协作取消成功 |
| `ANALYSIS_INTERNAL_ERROR` | 有限重试 | 未分类异常 |

Worker 记录完整 traceback 到受控日志，API 只返回错误码、`request_id` 和安全摘要。

## 13. 资源、性能和确定性

- Demucs 单任务默认 timeout 1,800 秒，Jetson GPU 队列并发 1；数值可由容量测试调整；
- Core 当前最大分析长度 420 秒，超过时必须在 quality flag 标注截断；
- 相同 `input_sha256 + pipeline_version + contract_version + seed` 应产生语义等价输出；
- 规范 JSON hash 使用 UTF-8、排序 key、无多余空白；
- 算法过程写到 run 专用临时目录，成功后由 Worker 原子发布，失败后按保留策略清理；
- 外部 adapter 环境包括鼓、Bass、风格、乐器、和弦命令及 Essentia Discogs 模型；每个路线必须独立超时、版本化和记录是否执行。

## 14. 算法团队交付物

每次发布必须同时交付：

1. Python adapter/CLI，输入输出遵循本合同；
2. 每种 artifact 的 JSON Schema 文件；
3. 至少一个成功、degraded、unavailable、失败的匿名 fixture；
4. 模型名称、hash、许可证、版本和部署路径清单；
5. CPU/GPU、内存、磁盘、平均/p95 耗时报告；
6. 验证集、指标、适用范围和不可声称内容；
7. 与上一版本的回归差异和迁移说明；
8. 不依赖 FastAPI 请求上下文的单元测试入口。

## 15. 后端接入验收

- Worker 在写库前能拒绝 schema 错误和 NaN；
- 同一 Run 的 artifact 可追溯 pipeline/model/input hash；
- optional 模型失败能形成 degraded/partial，而不是整条任务永久 running；
- 低置信 Downbeat 输出空/needs_review，不生成虚假的确定小节；
- `candidate_only`/`unavailable` 字段不进入普通用户确定标签；
- Stem 文件全部经过大小/hash/媒体探测后才标记 ready；
- App DTO 和 RK Manifest 通过明确投影生成，不返回整块算法原始 JSON；
- 任何算法升级都能并存旧 Run，并通过 `current_analysis_run_id` 原子切换和回滚。
