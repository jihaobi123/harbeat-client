# V3 realtime audition implementation plan

> **For agentic workers:** Execute locally with the executing-plans workflow. No delegation is required for this bounded prototype.

**Goal:** Publish a mobile-browser audition in which next/energy/style requests choose future cue windows and audio is mixed live, with downloadable plan and audio-thread timing logs.

**Architecture:** Static, independently deployed Vite entry plus versioned source-derived dataset. Six existing Hip-Hop songs (Trap/Grime) retain raw bar grids, SongFormer labels and manifest-bound vocals. FFmpeg prepares ONLY pitch-preserving entry-window assets; Web Audio schedules original/native body and tempo-prepared entry, live V3-parameter EQ and linear fades. No rendered pair/set audio is served. AudioWorklet reports render-quantum observations, explicitly not speaker latency. Original V3 is immutable; browser EQ/limiter is a separately named implementation, not byte-identical DSP.

**Tech Stack:** TypeScript, React, Web Audio + AudioWorklet, Python/FFmpeg asset preparation, Vitest, Playwright. Existing Jetson static hosting + Aliyun relay. No production backend restart or auth changes.

## Scope and acceptance
- Six confirmed Hip-Hop demo source identities; demonstrate Trap/Grime changes only.
- Raw bars provide exits and entry windows; no bar extrapolation or semantic confidence fabrication.
- Two/four-bar template candidates, source-conditioned vocals, local energy heuristic and actual tempo ratio recorded.
- Cold assets keep A playing; loading uses generation IDs; plan is recomputed after preparation.
- Cancel/replan before lock; defer ordinary requests while mixing; stop always fades and clears sources.
- Shared AudioContext schedule; native B body resumes at source entry end after overlap; no playbackRate pitch shift.
- Worklet logs armed/start/restore/handoff frames, observed quantum and message delivery time separately.
- Desktop and narrow viewport controls, full plan explanation and JSON export.
- Verify synthesis output, requests during prepare/mix, source end, latency budget, stale tasks, real public playback.
