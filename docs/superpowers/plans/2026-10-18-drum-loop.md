# Drum loop audition implementation plan

> Execute inline using executing-plans, delegate isolated UI and player units; use requesting-code-review for independent review.

**Goal:** A conditional, controlled one-bar drum loop comparison with two thinning examples and one stable control when measured evidence supports them.

**Architecture:** Read existing frozen pairs + formal user choices; source-bound drum profiling selects exact earlier source bar and final-two-bar application. Source-only renderer provides master/bass/drum/loop clips. New player adds only the drum replacement correction to the frozen bass strategy. Separate durable A/B UI and ordering evidence.

**Tech Stack:** TypeScript/React/Vite/Web Audio, Python/numpy/ffmpeg, existing NAS manifests.
