# HarBeat 公网网页端视觉改版设计

日期：2026-08-31  
范围：Jetson 公网网页端，包括登录注册、原网站全部功能页和 `/annotate` 公共标注工作台

## 背景

现有网页已经具备登录注册、私人曲库、歌单、搜索、推荐、DJ 功能、播放器和公共标注工作台。页面目前有粗边框和街头配色，但字体、卡片、导航、表单及数据密集区的规则不够统一，离参考图的编辑画册感还有明显距离。

这次只改网页的视觉和响应式排版。账号、页面内容、操作能力、路由、接口与标注数据都保持原样。Flutter 手机端不在本轮范围内。

## 已确认的设计方向

采用 A「编辑台 / Editorial Workbench」。它保留桌面网页的多栏效率，把参考图中的暖白纸张、粗黑框、窄体大标题、编号模块和高饱和色块整理成一套可复用的网页视觉系统。

插画维持中等密度，只出现在登录页、首页主视觉、空状态和少数功能引导区。标注时间轴、表单、歌曲详情和其他数据密集区域不放装饰。

## 不变的内容

- 登录、注册、退出和登录状态检查不变。
- `/` 与 `/annotate` 的路由和跳转关系不变。
- 曲库、歌单、搜索、推荐、DJ Session、DJ Control、Profile、上传和导入歌单的功能不变。
- 公共 Pilot 歌曲、机器建议、段落标签、四种音乐元素状态、循环试听、Stem 试听、Revision 和保存逻辑不变。
- API 地址、请求字段、响应结构、认证方式和后端数据目录不变。
- 原网站与公共标注工作台继续共用同一套账号。

文案可以调整大小写、换行和中英文视觉层级，但不能改变含义，也不能隐藏现有入口。

## 视觉语言

### 色彩

基础色使用暖白和纸张米色，正文为接近纯黑的深色。页面只保留四种高饱和强调色：

- 荧光绿用于主要操作、当前状态和在线状态。
- 钴蓝用于重点任务、选中歌曲和主视觉卡片。
- 橙红用于警告、破坏性操作及少量次级宣传卡片。
- 暖黄用于插画高光和辅助提示。

颜色不能成为状态的唯一表达。选中、错误和完成状态还要有文字、图标或边框差异。

### 字体

英文标题使用本地打包的窄体粗黑展示字体，中文标题使用粗黑中文字体，正文使用清晰的中文无衬线字体。字体文件随前端发布，不依赖 Google Fonts 或其他外部字体服务。

大标题允许紧凑换行，但表单标签、时间、BPM、Revision 和时间轴刻度保持易读，不使用装饰字体。

### 线框与层级

主要卡片使用 3 至 4 像素黑色边框和硬边阴影。输入框、状态标签和次级按钮使用 2 像素边框。圆角控制在小范围，避免页面重新变成常见的圆角卡片风格。

页面模块使用「编号 + 名称」标题条，例如 `01 歌曲`、`02 元素出现时间`。编号只承担导航和层级，不改变原有任务顺序。

主要按钮为荧光绿底，普通按钮为白底，警示按钮为橙红底。按钮的悬停、按下、禁用和键盘聚焦状态使用同一套规则。

### 插画与图标

新增插画必须是 HarBeat 原创内容，主题可使用唱片、耳机、音箱、调音台、舞者动作线和节奏符号。不能照搬参考图中的人物、姿势或具体构图。

界面现有的表情符号图标会替换成统一的黑色线描 SVG 图标。图标语义不变，并保留可访问名称。

## 页面设计

### 登录与注册

页面分成品牌主视觉和表单两部分。桌面端左右或上下组合，窄屏改为单列。登录与注册继续使用同一个表单容器，切换时不改认证流程。

错误信息放在字段上方的橙红提示框中。提交中、禁用和失败状态不改变现有行为。注册时的舞种与水平选择完整保留。

### 原网站框架

桌面端继续使用顶部栏、左侧导航、主内容区和底部播放器：

- 顶部栏保留品牌、搜索、导入歌单和上传入口。
- 左侧导航保留 Library、Search、Discover、DJ Session、DJ Control、Profile、公共标注工作台、歌单和账号区域。
- 主内容区中的卡片、列表、详情、表单和弹窗套用统一的编号标题条与线框规则。
- 底部播放器保持常驻，改成黑底控制条；进度与当前播放状态使用荧光绿。

移动端使用纵向卡片。底部主导航归为音乐、发现、DJ、标注和我的，原有入口放入对应分组；没有任何功能被删除。播放器缩成固定迷你控制条，展开后显示完整控制。

### 公共标注工作台

桌面端保留高密度工作区：左侧是 Pilot 歌曲列表，右侧依次是播放控制、元素出现时间、段落与机器建议、保存状态。歌曲列表和播放控制在长页面中保持可见。

四条元素时间轴使用一致的行高、刻度和选中状态。人声、鼓、贝斯和旋律可以保留各自的识别色，但所有文本都满足对比度要求。拖拽区间、播放头、机器概率、人工状态和当前选择必须能一眼区分。

在窄屏上，歌曲列表改为抽屉或顶部选择器；播放控制和保存操作固定在屏幕边缘。时间轴允许横向滚动，不压缩到无法操作。Stem、循环、快捷键提示和 Revision 信息仍然可见。

存在未保存内容时，离开页面和退出登录仍然触发现有确认逻辑。

### 弹窗、空状态和异常状态

上传、歌单导入及其他弹窗沿用相同的黑框标题条。移动端可变为底部面板或接近全屏的单列布局，字段与操作顺序不变。

加载、空列表、接口失败、无音频、保存冲突和登录过期都使用统一状态卡。插画只用于空状态；错误信息必须直接说明发生了什么，并保留现有重试或重新登录入口。

## 组件边界

新增一层纯视觉组件，不让它读取业务数据：

- `EditorialShell`：页面背景、内容宽度和响应式框架。
- `NumberedSection`：编号标题条和内容容器。
- `EditorialButton`、`StatusTag`、`EditorialField`：按钮、状态与表单外观。
- `EditorialModal`：桌面弹窗和移动端面板。
- `BrandIllustration`：受控的原创插画容器。
- `EditorialIcon`：统一 SVG 图标入口。

现有业务组件继续负责取数、状态和操作。优先通过视觉组件和样式类改造，不在视觉层复制歌曲、播放、标注或认证逻辑。

## 数据流与状态

数据流保持不变：页面继续使用现有 Store 与 API Client，业务组件把状态传给视觉组件。视觉组件只接收文本、状态和事件回调，不主动请求接口。

加载、成功、空数据、禁用、错误和未保存状态都要有明确外观。视觉改版不能吞掉接口错误，也不能把原有确认弹窗替换成静默跳转。

## 响应式与可访问性

- 桌面宽度从 1024 像素起保留多栏；768 至 1023 像素减少侧栏宽度并允许部分模块换行；低于 768 像素使用单列卡片。
- 所有可点击控件保留可见的键盘焦点，触控目标不小于 44 像素。
- 正文和交互文字满足 WCAG AA 对比度。荧光色不承载小号正文。
- 支持系统减少动态效果设置；硬边位移反馈在该设置下关闭。
- 时间轴、滑块、弹窗和抽屉保持键盘操作与屏幕阅读器标签。
- 页面在中英文混排、长用户名、长歌名和空数据时不能溢出。

## 资源和发布

字体、SVG 图标和插画随前端包发布。插画优先使用可压缩 SVG；需要位图时提供适配尺寸和现代格式，不能阻塞首屏登录或标注工作台。

本轮只替换前端静态资源和构建产物。Jetson 上的 API、持久化目录和 Nginx 路由保持不变。发布继续采用新 release 目录验证后切换的方式，出现问题时可恢复上一个前端版本，不影响已有标注。

## 验收

### 自动检查

- 现有前端测试全部通过。
- 为新增视觉组件补充状态和交互测试。
- 登录、主站和 `/annotate` 的路由测试继续通过。
- TypeScript 检查与生产构建通过。
- 前端不能新增对外部字体或运行时插画服务的依赖。

### 浏览器验收

至少检查 1440、1024、768、390 像素四种宽度：

- 登录、注册和错误提示完整可用。
- 主站所有导航入口、歌单、搜索、上传、导入、播放器和 DJ 页面仍可操作。
- `/annotate` 能选择歌曲、播放原音和 Stem、编辑元素区间、修改段落、保存 Revision，并在刷新后读回自己的结果。
- 未保存离开确认、登录过期、接口失败和保存冲突仍有明确反馈。
- 长歌名、空歌单、空标注、加载状态和移动端时间轴没有遮挡或不可点击区域。

### Jetson 上线验收

先在临时端口检查静态资源、字体、插画和 API 请求，再切换公网版本。上线后同时抽查 `/` 与 `/annotate`，确认旧账号可登录、Pilot 数据未变化、两名标注者的数据仍然隔离。

## 完成标准

网页端所有现有页面都使用同一套编辑台视觉语言；桌面端仍适合长时间管理和标注，手机端可以完成主要流程。功能、数据、接口和用户已有内容没有变化，线上版本可独立回滚。
