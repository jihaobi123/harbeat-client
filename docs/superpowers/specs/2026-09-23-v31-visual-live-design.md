# V3.1 候选版：图解、实时接歌与二十首验证

用户已授权直接实施，选择先在 Hip-Hop／Trap／Grime 内扩到约二十首。V3.1 暂为候选名，是否正式采用由扩大试听后的反馈决定。保留冻结 V3、原保护版和逐行证据入口。

主页面分为“实时接歌”和“同条件对照”。图解以 A、B 两条原曲时间轴及统一转场时间轴为主，标出模型段落、人声检测区间、进入片段、A 完全退出／B 正文接管点、两条增益曲线和可能的人声区间重合。解释只回答为什么等到这个点、为什么选这段、实际如何交接；原始行号及完整 JSON 折叠保留。把模型段落和活动检测标为候选，不标成歌词语义真值。

实时接歌复用已经被用户接受的 acoustic-v1 硬约束和 V3 WebAudio EQ，不增加能量或风格评分。播放中可以选择下一首、准备素材、请求切换、取消未锁定计划、暂停、拖动进度。素材未准备好时继续 A，加载后按当前时间重新规划；找不到合格窗口就显示原因，不退回普通算法，不为了快而跳过保护。

对照模式使用相同 A、B、请求位置，分别运行冻结普通 V3 的下一首规则与保护规则。短试听可跳到各自混入前四秒，保留原来的计划和等待时间，明确这不是在跳转位置重新选点。每个曲对保存等待、重叠检测、选点、素材及执行日志，并可记录试听偏好。不能用客观重合量冒充主观音质评分。

样本以已分析的曲风候选、身份绑定、BPM／人声密度／结构多样性选取，优先保留原六首，再补十四首。选择不以保护算法是否成功为前提；无窗口与证据缺失也保留覆盖结果。音频沿用最多前 150 秒的浏览器演示范围，以保证两路 PCM 在现有 192 MB 缓存内；页面明确时长限制。先检查已有分析，缺少必要测量才补算。仅预制单首进入片段，整段混音在浏览器实时执行。
