# HarBeat 移动端产品手册与交互原型设计规格

- 版本：1.0
- 日期：2026-08-18
- 状态：方案已确认，等待书面规格审核
- 读者：产品经理、设计师、Flutter 前端、后端、RK3588 工程师、合作方
- 完整产品规格：[2026-08-18-harbeat-mobile-app-product-design.md](./2026-08-18-harbeat-mobile-app-product-design.md)
- 计划交付物：`harbeat-mobile-product-handbook.html`

## 1. 目标

制作一个无需安装、无需启动服务器、双击即可离线打开的单文件 HTML。它需要同时完成三件事：

1. 用较短时间向合作方和团队成员讲清 HarBeat 手机 App 的定位、范围和核心体验。
2. 用可点击的手机界面演示音乐发现、曲库管理、设备连接和 Pad 同步闭环。
3. 向前端提供页面编号、状态、数据和验收说明，减少口头转述造成的理解偏差。

最终交付时发送两个文件：

- `harbeat-mobile-product-handbook.html`：精简产品手册、关键路径原型和前端标注。
- `2026-08-18-harbeat-mobile-app-product-design.md`：完整、可编辑的产品规格和契约说明。

HTML 必须可以单独阅读；Markdown 是更完整的需求真源。

## 2. 已确认的设计决策

### 2.1 受众

网页同时服务两类读者：

- 合作方、团队成员和非研发人员：需要快速理解产品价值和使用流程。
- 前端、后端、RK3588 与测试人员：需要明确页面、状态、数据来源和验收条件。

### 2.2 网页外壳

采用三模式切换结构：

1. 产品手册
2. 交互原型
3. 前端标注

三种模式位于同一个 HTML 文件中，不生成三个独立站点。

### 2.3 原型深度

采用关键路径原型，不追求覆盖全部 P0 页面：

- 9 个主页面。
- 3 条完整任务闭环。
- 少量关键弹层和状态反馈。
- 登录、全部错误页和后台管理写入文档，但不制作成主原型页面。

### 2.4 视觉方向

采用“现代音乐产品为骨架，地下刊物为品牌层”的混合方向：

- 约 80% 的界面遵循成熟音乐产品的导航、卡片、留白和操作习惯。
- 约 20% 的视觉表达来自街头海报、Battle 传单和地下刊物。
- 街头表达主要用于标题、贴纸、专题推荐和活动封面。
- 设备状态、同步确认、错误提示和主要按钮保持规整，不为追求风格牺牲可读性。

## 3. 文件与内容关系

### 3.1 信息真源

| 内容 | 主要真源 | HTML 中的处理方式 |
|---|---|---|
| 产品定位和职责边界 | 完整产品规格 | 精简摘要 |
| 页面编号和流程 | 完整产品规格 | 可视化并可点击 |
| 状态、数据与 API 契约 | 完整产品规格和后续 OpenAPI | 展示前端所需摘要，明确标记 Mock |
| 视觉与交互方向 | 本文档和最终 HTML | 完整展示 |
| 最终接口字段 | 后端 OpenAPI / WebSocket 文档 | 不在原型中伪装为已确定 |

当 HTML 和 Markdown 出现冲突时，团队应先检查版本日期，再以较新的完整产品规格和已确认接口契约为准。

### 3.2 文件摆放

两个文件默认放在同一目录中。HTML 可以使用相对链接指向完整 Markdown，但自身不能依赖 Markdown 才能正常显示。

HTML 顶部应显示：

- 产品名称。
- 文档版本和日期。
- “演示数据 / Mock API”标识。
- 完整规格文件名。
- 重置演示按钮。

## 4. 单文件网页的信息架构

### 4.1 全局框架

桌面端采用以下结构：

- 顶部：HarBeat 品牌、版本、模式切换、重置按钮。
- 左侧：当前模式的章节或场景导航。
- 中央：正文、流程图或手机原型。
- 右侧：仅在“前端标注”模式出现页面目的、状态和数据说明。

在较窄屏幕上：

- 顶部模式切换可以横向滚动。
- 左侧目录收起为抽屉或章节选择器。
- 手机原型保持完整纵向比例。
- 右侧标注移动到手机原型下方。

### 4.2 产品手册模式

产品手册不复制完整 Markdown，而是保留能独立理解产品的内容：

1. 一句话定位。
2. App、云端、RK3588 和实体控制器的职责关系。
3. 主要用户和核心任务。
4. 手机独立模式与连接设备模式。
5. 底部导航和音乐页内部结构。
6. 3 条关键用户旅程。
7. 9 个原型页面的页面树。
8. 推荐、曲库、Pad 和同步的关键规则。
9. P0 范围与明确不做的事项。
10. 前后端协作和交付检查清单。

每一章节都提供“查看原型中的对应步骤”入口。

### 4.3 交互原型模式

原型模式包含：

- 场景选择：发现音乐、搜索导入、配置设备。
- 当前步骤名称和进度。
- 手机界面画框。
- 上一步、下一步和重新开始。
- 可点击热点，不依赖读者按固定顺序操作。
- 关键动作完成后的短反馈。

读者可以通过场景导航直接跳到任一闭环，也可以从头连续演示。

### 4.4 前端标注模式

前端标注模式使用同一套手机页面，右侧展示：

- 页面编号和页面名称。
- 页面目的。
- 进入条件和退出条件。
- 主要操作与次要操作。
- 加载、空、错误、离线和权限状态。
- 所需数据对象和字段摘要。
- 待后端确定的接口或事件。
- 埋点事件。
- 验收条件。

接口名称和字段如未确认，必须使用 `Mock`、`待确认` 或 `示例` 标签，不能让前端误以为已经形成正式契约。

## 5. 关键路径原型范围

### 5.1 主页面

为了避免与完整产品规格中的正式页面编号冲突，原型使用 `V01` 至 `V09` 作为“演示视图编号”。正式页面编号仍以完整产品规格为准。

| 原型视图 | 对应正式页面 | 页面 | 在原型中的任务 |
|---|---|---|---|
| V01 | H01 | 首页 | 查看设备状态、最近内容和推荐入口 |
| V02 | M01 的推荐分区 | 音乐 / 推荐 | 浏览按舞种与个人行为生成的音乐推荐 |
| V03 | M01 的搜索分区 | 搜索 / 导入 | 统一处理站内搜索、外部歌单链接和本地文件 |
| V04 | M01 的子页面 | 歌曲详情 | 试听、查看 BPM/调性/能量/段落并保存 |
| V05 | M01 的曲库与歌单分区 | 曲库 / 歌单 | 验证保存或导入结果，管理个人内容 |
| V06 | D01 未连接状态 | 设备列表 | 查看最近设备，输入局域网地址 |
| V07 | D01 配对状态 | 配对 | 输入配对码并确认目标设备 |
| V08 | D01 已连接状态 | 设备面板 | 查看在线、资源和同步版本状态 |
| V09 | D02 | Pad 编辑 | 编辑 8 个独立 Pad 槽位并发起同步 |

`P01 准备向导`和`L01 正在使用`保留在完整产品规格中，但不属于这次关键路径原型的 9 个主视图。

### 5.2 关键弹层与全局反馈

原型包含以下非主页面状态：

- O01：保存到曲库 / 选择歌单。
- O02：同步并覆盖设备确认。
- O03：保存成功或同步成功 Toast。
- B01：设备掉线提示条。
- PLY01：底部试听播放器。

### 5.3 闭环一：发现音乐并保存

```text
V01 首页
  → V02 推荐
  → V04 歌曲详情与试听
  → O01 选择曲库或歌单
  → O03 保存成功
  → V05 曲库中可见
```

关键规则：

- 推荐只学习个人舞种偏好和手机端个人行为。
- 活动 Session 的播放行为不写入个人推荐画像。
- 试听不等于下载；资源不可用时必须明确显示原因。

### 5.4 闭环二：搜索或导入音乐

```text
V02 音乐入口
  → V03 搜索 / 导入
  → V04 匹配结果或歌曲详情
  → O01 选择保存位置
  → V05 曲库中可见
```

关键规则：

- 搜索、本地上传和外部链接导入共用一个入口，但需要清楚区分来源。
- QQ 音乐、网易云等外部链接在 P0 只承诺元数据解析和合法资源匹配。
- 不把未授权的第三方完整音频下载写成正式产品能力。
- 导入失败要区分链接无法识别、元数据缺失、资源不可用和网络失败。

### 5.5 闭环三：设备连接、Pad 配置与同步

```text
V06 设备列表
  → V07 局域网地址与配对码
  → V08 设备面板
  → V09 Pad 编辑
  → O02 覆盖确认
  → O03 同步成功
  → V08 显示设备新版本
```

关键规则：

- P0 使用最近设备、手动局域网地址和配对码。
- App 先保存本地或云端编辑版本，再由用户明确发起同步。
- 同步必须说明将覆盖哪台设备、哪个版本和哪些 Pad。
- 手机断开后，RK3588 和实体控制器仍可使用已同步内容。
- 实体控制器核心按键固定，App 只配置 8 个独立自定义 Pad 槽位。

## 6. 演示状态与数据

### 6.1 原型状态模型

单文件 HTML 使用内存中的演示状态，不调用真实后端。最少包含：

```text
currentMode
currentScenario
currentScreen
selectedTrack
savedTrackIds
selectedPlaylistId
deviceConnectionState
pairingState
appPresetVersion
devicePresetVersion
padSlots[8]
syncState
```

点击“重置演示”后恢复统一初始状态。

### 6.2 演示数据

需要准备少量稳定的模拟数据：

- 8 至 12 首歌曲。
- 3 个主要舞种，例如 Popping、Hip-Hop、Locking。
- 2 至 3 个个人歌单。
- 1 台在线设备和 1 台离线历史设备。
- 1 套包含 8 个槽位的 Pad 预设。
- 资源可用、仅元数据、不可用三种歌曲状态。

演示数据应使用原创虚构名称或有明确授权的内容，不使用受版权保护的真实封面资源。

### 6.3 连接与同步演示

原型必须明确显示它在模拟连接：

- 点击配对后经过短暂加载，进入连接成功状态。
- 同步前显示 App 版本与设备版本。
- 确认后显示进度，再显示同步成功。
- 可手动触发设备掉线状态，用于演示 B01。

不模拟真实局域网扫描、WebSocket 或 RK3588 通信。

## 7. 视觉系统

### 7.1 配色

建议首版使用以下设计 Token：

| Token | 建议色值 | 用途 |
|---|---:|---|
| Paper | `#F2EFE6` | 页面基础背景 |
| Ink | `#121311` | 正文、强对比设备卡 |
| Cobalt | `#2457FF` | 主操作、选中状态、设备入口 |
| Acid | `#DCFF32` | 贴纸、成功、在线和品牌强调 |
| Signal Red | `#FF4D36` | 警告、重点 Pad、活动强调 |
| White | `#FFFFFF` | 内容卡片和浮层 |

酸性绿不能大面积作为正文背景；红色不能与普通品牌装饰混用到让用户误判为错误状态。

### 7.2 字体

- 正文和控件：系统无衬线字体栈，保证离线和跨平台显示。
- 大标题：使用系统粗体或压缩视觉效果，避免外部字体依赖。
- 英文品牌词可以全大写和紧凑字距。
- 中文正文不使用过度压缩或装饰性字体。

### 7.3 形状与构图

- 主内容卡片以 12 至 20 px 圆角和清晰留白为主。
- 贴纸、专题推荐标题和活动标签允许轻微旋转、硬边框和错位阴影。
- 设备操作卡、输入框和确认弹层不得倾斜。
- 可点击元素必须通过形状、颜色或悬停状态表达，不依赖装饰猜测。

### 7.4 动效

- 模式切换、页面切换和弹层使用 180 至 240 ms 的短动效。
- 同步进度允许使用阶段动画，但不伪装成真实耗时。
- 支持 `prefers-reduced-motion`，减少或关闭非必要动效。

## 8. 单文件技术约束

### 8.1 离线要求

最终 HTML：

- 不引用 CDN。
- 不加载外部字体。
- 不调用真实接口。
- 不依赖图片目录、CSS 文件或 JavaScript 文件。
- 图标使用内联 SVG。
- 示例封面使用 CSS 或内联 SVG 生成。
- 在 `file://` 环境下可以正常打开和交互。

### 8.2 兼容范围

至少验证：

- macOS Chrome 最新稳定版。
- macOS Safari 最新稳定版。
- Windows Chrome 或 Edge 最新稳定版。
- 1280 px 及以上桌面宽度。
- 768 px 左右平板宽度。

手机浏览器可以阅读，但该文件首先是一份桌面评审和交付材料，不要求模拟成正式移动应用。

### 8.3 可访问性

- 模式、场景和主要操作可使用键盘访问。
- 焦点状态清楚可见。
- 颜色不是状态的唯一表达方式。
- 交互按钮具有可读文本或 `aria-label`。
- 正文保持足够的字号与对比度。

## 9. 产品手册中的前端交付内容

HTML 的前端标注模式需要覆盖以下最小信息：

| 类别 | 说明 |
|---|---|
| 页面 | 编号、名称、目的、入口与出口 |
| 组件 | 顶部栏、底部导航、歌曲卡、设备卡、Pad 槽位、弹层、Toast |
| 状态 | 加载、空、错误、离线、权限、资源可用性、同步版本 |
| 数据 | 字段摘要、示例值、数据真源、Mock 标识 |
| 事件 | 用户动作、WebSocket 候选事件、埋点候选事件 |
| 验收 | 页面级 Given/When/Then 或等价检查项 |

原型用于减少歧义，不代替 OpenAPI、WebSocket 事件表或最终视觉尺寸稿。

## 10. 明确不包含的内容

本次单文件原型不包含：

- 真实登录和账号系统。
- 真实音乐搜索、上传或第三方平台下载。
- 真实推荐算法。
- 真实局域网发现、配对或 WebSocket 通信。
- 真实音频文件和受版权保护的专辑封面。
- 低延迟音频处理、自动 DJ 或 Stems 控制。
- 完整后台管理系统。
- 所有错误页的逐页高保真设计。

这些内容如属于 P0，会在完整 Markdown 中保留需求、状态和验收说明。

## 11. 验收标准

### 11.1 文件验收

- 只发送 HTML 时，对方仍能理解产品定位、关键流程和页面范围。
- HTML 与 Markdown 放在同一目录时，可以从 HTML 找到完整规格文件名。
- 断开网络后重新打开 HTML，页面和交互仍正常。
- 页面没有外部资源加载失败。

### 11.2 内容验收

- 产品手册模式可以在 5 至 10 分钟内讲清产品。
- App、云端、RK3588 和实体控制器的职责没有混淆。
- 手机独立模式与连接设备模式边界清楚。
- 推荐画像与活动 Session 行为明确分离。
- 第三方音乐链接没有被描述为未授权下载能力。

### 11.3 原型验收

- 3 个场景都可以从入口走到明确的完成状态。
- 9 个主页面可以通过场景导航直接访问。
- 保存歌曲后，V05 中能看到状态变化。
- 编辑 Pad 后，必须先保存 App 版本，再确认同步到设备。
- 同步成功后，V08 显示 App 与设备版本一致。
- 触发掉线状态后，界面明确说明哪些操作不可用。
- 点击重置后恢复一致的初始数据。

### 11.4 前端标注验收

- 每个主页面都有页面目的、核心操作、状态和数据摘要。
- 未确认的 API 与字段都有明显 Mock 或待确认标识。
- 前端可以仅凭 HTML 和完整 Markdown 拆出页面与组件任务。
- 后端可以从材料中识别需要确认的数据对象、状态枚举和事件。

## 12. 后续执行顺序

在本文档审核通过后：

1. 编写实现计划，明确 HTML 结构、组件、数据和验证步骤。
2. 先搭建三模式外壳和视觉 Token。
3. 实现产品手册摘要。
4. 实现 9 个主页面和 3 条场景状态机。
5. 实现前端标注模式。
6. 验证离线、响应式、键盘访问和关键路径。
7. 将最终 HTML 与完整 Markdown 一起交付。

未经审核，不进入实际单文件 HTML 的正式制作。
