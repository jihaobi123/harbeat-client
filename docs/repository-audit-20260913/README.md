Android 网络访问需要 INTERNET 权限，见 [Android 官方网络连接说明](https://developer.android.com/develop/connectivity/network-ops/connecting)。前端需在源码中修正并重新构建；仅调整服务器接口不能解决这个安装包的权限缺失。

只进行了静态核验，未安装、运行或推断所有页面操作。单凭 APK 不能可靠还原完整请求/响应 DTO，也不能把未搜到路径当成“完全没有 API”。需要前端提供对应源码分支/commit，或源码压缩包、页面列表及已接入接口说明。

## 4. 用户明确要求的新职责边界

| 部件 | 本轮职责 | 不应承担 |
|---|---|---|
| Jetson | 预处理 Worker、业务 API、任务管理、数据库目录、发布结果读取与授权 | RK 上的实时混音/播放和姿态识别 |
| NAS | 音频和不可变分析产物，含版本与 hash | 直接暴露给公网、充当用户权限数据库 |
| 阿里云 | 公网 HTTPS 入口，将获准请求通过受控链路转发至 Jetson | 默认为第二套独立业务真相库、承担实时音频计算 |
| 手机 | 登录、浏览/选歌、提交准备请求、展示真实准备进度 | 应用层下载全部音轨后再转发给 RK |
| 手机热点 | RK 的网络接入；网络层流量转发 | 等同于 App 音频文件中转服务 |
| RK3588 | 主动连接公网入口、获取指定曲目资产、缓存校验、混音算法、实时播放 | 后端负责人的端内开发范围 |
| 戒指/手环 | 由用户负责的 RK/硬件链路处理姿态与音乐操作 | Jetson/手机业务后端接管手势协议 |

后端负责人实现服务器侧供 RK 消费的合同，并用模拟 RK 验收；RK 端下载器、音频引擎和实际消费由用户负责。手机前端代码不因后端任务书而转交给后端负责人。

建议数据链路：

1. 手机通过阿里云 HTTPS 请求 Jetson 曲库；用户选择曲目与目标 RK。
2. Jetson 校验用户权限、曲目版本和目标设备归属，创建持久化准备/同步任务。
3. RK 经手机热点主动向阿里云入口领取自己的任务。不能依赖 Jetson 直接连入热点后的 RK 私有 IP。
4. Jetson 提供冻结版本的下载清单；RK 经公网网关下载 NAS 资产并校验。
5. RK 回报实际下载/校验状态，Jetson 保存状态；手机读取状态。
6. 混音与播放在 RK 本机进行。文件已下载、资产已校验、混音引擎可播放是不同状态，后端不得自行宣布播放成功。

以上为设计建议，尚未宣布现有代码已经打通该链路。低延迟手机播放控制的具体协议留待手机源码和混音文件确认，不在本轮偷偷改为云端实时音频控制。

## 5. 代码现状与需要补齐的连接层

| 能力 | 当前证据 | 判断/下一步 |
|---|---|---|
| 标准化预处理与 NAS 发布 | `app/modules/library/same_style_preprocess.py`、`scripts/run_same_style_preprocess.py`、`deploy/jetson/` | 保留，作为 Worker 调用对象，不重写算法 |
| SongFormer 正式段落 | `analysis.py` 及 `experiments/run_songformer_isolated.py` | 保留现用运行器，不启用标签修正实验替代主结果 |
| MDX23C 与人声标记 | `music_analysis/drum_analysis/`、上一轮 `vocal_activity.py` | 纳入统一源码；保留 ADTOF 禁用策略 |
| 用户/曲库/歌单 API | `app/modules/auth`、`library`、`playlists` | 可复用起点，不是完整生产后端 |
| 旧曲库模型 | `LibrarySong` 含 source_path、stems、analysis_status 和多项 JSON 字段 | 需与 NAS track_id/run_id/发布版本建立显式映射，不能按歌名关联 |
| 旧媒体下载 | `app/modules/assets/router.py` 按 upload_dir 返回文件 | 没有该路由内的用户/设备授权；不能原样暴露为 NAS 公网下载入口 |
| 旧 Manifest | `app/modules/manifest/__init__.py` 从 LibrarySong 生成；hash 默认可以为空 | 不是新 NAS Manifest 的直接导出；需做新版本 adapter，而非继续增加临时兼容字段 |
| 后台分析 | `background_tasks.py` 直接持有 DB session、写 LibrarySong；启动恢复还使用进程内线程 | 独立持久 Worker、租约/重试/超时/幂等尚需完善 |
| 新 NAS → 手机目录 → RK 同步 | 两条数据链路目前分开 | 本轮重点新建：目录投影、权限、版本冻结、同步任务、进度与资产授权 |
| 数据库迁移 | 有专项迁移脚本与 create_all 开关；在审计基线未发现正式 Alembic 目录 | 不得把空库建表当作生产迁移完成，需要先做 schema 基线与旧数据对账 |
| 阿里云代理样例 | `deploy/cloud_gateway/app/main.py` 使用 request.body/resp.content 缓冲，路由方法未列 HEAD | 大音轨流式下载、Range/HEAD、超时与重试必须重新验收 |
| 登录安全 | 旧密码函数使用 SHA256(jwt_secret + password)，刷新 token 无持久轮换账本 | 需安全迁移，不能让新合同掩盖旧实现；禁止直接改 hash 导致旧用户失效 |

FastAPI 官方也区分普通 BackgroundTasks 与重计算 Worker，见 [官方说明](https://fastapi.tiangolo.com/tutorial/background-tasks/#caveat)。具体队列实现应在任务书选定一种并给出可运行模板，不能让负责人自行拼接多套方案。

| RK、戒指/手环代码 | 保留，明确由用户维护，与后端目录/任务隔离 | “不归后端负责”绝不是删除理由 |
| `experiments/` 整目录 | **不能直接删除** | 正式 SongFormer 运行器仍位于这里；先迁移运行器并修复调用/部署/测试 |
| `module/*` 远端分支 | 先按 SHA 登记历史/候选用途，不批量删除 | 负责人确认是否有未合并工作、是否完成备份 |

移出当前树不会自动缩小 Git 历史。清理历史、强推和删除远端分支是另一项高风险操作，不包含在默认清理动作里。

## 7. 后续整体迁移建议（不代表本轮已执行）

1. 以现用预处理分支为来源，建立独立统一开发基线；不在脏工作区直接切换、不覆盖 main。
2. 先提交/纳入本轮 Silero 等已部署增量；与运行版本做来源对账。
3. 建一个 START_HERE，明确 backend / mobile / RK 入口、当前状态、唯一合同与历史索引。
4. 给历史文档加版本标识；先做导航清理，再做目录搬迁。
5. 小提交迁移非代码制品；逐项检查导入、CLI、模型默认路径和部署脚本。
6. 对预处理合同、V2 手机 API、权限、资产同步做分组回归；不以模块单测替代端到端验收。不验收旧手机兼容性。
7. 发布候选分支供用户/RK/前端评审；确认后才决定默认分支切换和旧分支归档策略。
8. 编写新版后端负责人任务书、OpenAPI、下载清单 schema、fixtures 与模拟 RK 测试；明确 CURRENT / PARTIAL / MISSING / PROPOSED。

不进行：强推、批量合并、删除 NAS 数据、重跑全曲库、修改线上服务、替换 RK 混音代码、擅自纳入其他人的未提交修改。

## 8. 后续后端任务书必须落实的数据约束

- 保留现有 `same_style_track_preprocess 1.2.0` 和 `harbeat_vocal_activity 1.0.0`，新增“传输清单”外壳，不能把存储合同和网络 URL 混在一起。
- 一次选歌任务固定 track_id + analysis_run_id + manifest_sha256，并绑定匹配的 vocal 报告 hash；准备过程中不得再次解析 latest 漂移版本。
- 全部所选歌曲的基础 manifest、成功标记、master、4 个 stems、5 个 drums，以及匹配的人声报告/成功标记都应可获取。资产缺失不得假装完整。
- 新接口统一整数毫秒；旧 API 中以秒存储的字段通过适配层处理，不修改原始发布文件。
- API 只暴露不透明 asset_id 与获准的短期下载地址，不接受客户端任意 NAS 路径，不暴露挂载凭据、模型密钥或训练数据。
- 音轨按字节传输，提供长度、hash、媒体类型及断点恢复语义；透明转码会破坏 hash，必须另建版本化资产。
- 待补分析、已发布、正在下载、已校验、引擎可播放分开建模。`degraded` 不自动等于“缺文件”，也不等于“不能用”；应看模块状态和 quality_flags。
- 手机只提交选歌意图，RK 主动领取任务与下载；后台“通知”不能被写成公网主动连接 RK 私有地址。
- 同步状态由 RK 上报，用户只能读取自己获准设备/歌曲的状态。手机选歌不能顺便触发未授权的重新分析。
- 给初级后端负责人提供迁移脚本、路由/DTO 示例、任务状态机、错误码、模拟 RK、curl 样例、部署步骤与明确的验收表，而不是仅给框图。

## 9. 高风险变更及后续联调确认

1. 仅默认分支切换、历史分支删除、历史瘦身和线上数据迁移需要另行确认；低风险旧脚本归档已按用户要求执行。
2. 新 APK 可独立纳入制品交付，前端联调前提供修正网络权限后的构建；不要求先匹配旧仓库手机代码。
3. 新混音文件到达后，由用户确认 RK 所需运行数据及协议兼容版本；在此之前可设计完整资产传输，但不冻结混音参数或姿态控制协议。

已确认的边界无需重复选择：后端负责人不负责 RK 端混音实现、不负责戒指/手环到 RK 的操作。
