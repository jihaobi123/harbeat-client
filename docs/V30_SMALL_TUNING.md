# V3 小幅调整与 EQ 对照

试听入口：https://8.136.120.255/analysis-lab-static/v30-tuning-20260924/index.html

本轮以 20 首试听曲目的原 V3 目录为基线。用户偏好原 V3 的渐进叠加，不接受把 A 保持到尾音结束后再快速退出。因此，本轮不用 V3.1 的保护入口或后续乐句版的增益保持曲线。

## 保持原状的部分

- 原 V3 选歌排序、18 秒等待范围、B 的 152 个进入窗口及预制变速素材。
- A 在整段混合过程中从 0.76 线性降到 0；B 同时从 0 升到 0.76。
- A 的滤波支路在混入后 20ms 内启用，B 在最后半小节通过干湿交叉恢复原声。
- B 接管后恢复原速、音频线程计时、边缘淡化及输出保护。
- 原 V3/V3.1 页面、历史会话和原有偏好存储。

## 小幅边界核验

首先运行原 V3 规划器并固定它选中的 B、进入片段、变速和时长。随后只比较原退出点与相邻的下一个小节，后者必须已存在于同一次原 V3 的可执行候选集合中。

核验检查原报告、母带、人声分轨指纹；退出前的四个实测拍点；人声活动及保护尾音；模型段尾距离；退出点前后 250ms 内的 VAD/RMS 分歧。来源缺失、拍网格不完整、相关证据冲突或没有明确改善时，保持原计划并显示原因。

如果相邻候选由“句中退出”变为“未落在检测人声活动内”，或两点均无人声且相邻点更接近模型段尾，才整体后移 A 的混入和退出时刻。重叠时长不变，不移动 B 的原曲片段，不改变原 V3 的人声占比检测和 EQ 触发规则。

这些证据来自已有声学分析，不是新增歌词语义识别。特别是保守并集可能把较长的人声活动合成一个候选，不能据此声称已经识别出完整歌词句子。下一小节首拍也不等于前一小节最后一拍的起点。

## 动态 EQ 只控制系数

固定模板保持 A 低频 −9dB、高频 −1.4dB；B 低频 −7dB、高频 +1.2dB，原规则触发人声冲突时 B 中频为 −5dB。

动态模式沿每个计划的时间映射读取 A/B 的源频段功率，以约 0.5 秒局部窗口测量、每不超过 0.25 秒生成一个控制点。B 的源时间乘以该素材的变速比例。dBFS 先换成功率，再按帧重叠时长平均；不直接平均分贝值。

低/高频根据模板处理后的源功率差计算：两侧差距超过 3dB 时，削弱偏强的一侧，差值乘 0.35，最多再衰减 3dB。修正量乘以 `4x(1−x)`，其中 x 为交接进度，使影响集中在两曲同时可听的中段。

B 中频在原模板附近根据同一时刻的声学人声活动占比调整，最多 ±2dB。所有频段控制值每秒最多变化 3dB。原来的增益与干湿曲线保持不动。源码、日志同时保留目标系数与实际限速后的系数，原始频段帧行号从 1 开始。

这是有界的待试听控制规则，不是已验证的最佳 EQ，也不是实时麦克风或输出信号的反馈控制。分析频段与 Biquad 滤波器响应不完全相同。缺少源功率或来源不匹配时，动态选项明确不可用，不悄悄替换为固定 EQ。

## 怎么比较

页面提供四项：原 V3＋固定 EQ、原 V3＋动态 EQ、小幅核验＋固定 EQ、小幅核验＋动态 EQ。

先比较前两项，只判断 EQ。再比较第一、第三项，只判断选点；若显示后移 0 秒，两者的音频处理相同。第四项用于与第三项比较，不能一次同时改变选点和 EQ 后归因。

本轮偏好键为 `harbeat-v30-small-tuning-feedback-v1`，不写原 V3/V3.1 的键。完成交接并收到音频线程观察后才可评分。原始会话写入现有会话存储，可从分析平台查看。

## 验证与当前覆盖

- 原 20 组请求位置中 19 组存在 V3 计划；失败样本保留。
- 157 次同曲对位置检查中，132 次存在计划；所有执行候选保持 B 素材、变速和完整重叠时长。
- 另检查 1,900 个曲对/位置组合，未找到满足本轮保守条件且应后移的实例。没有为了制造变化放宽条件，也不能宣称本轮已经证明边界识别更准。
- 固定/动态 EQ 在可执行样本上选择相同计划；自动测试核对音频源时钟、全部增益和干湿控制事件一致。
- 浏览器四项对照完成同一曲对的 6.426 秒交接，音频线程观察与计划相差不超过 1.34ms。首次冷缓存准备约 58 秒，后三次复用三份解码素材，准备约 0–0.1ms；这不是所有网络/设备的延迟承诺。
- 最终部署页完成一次用户触发的实时动态 EQ 接歌，三项音频线程观察齐全，浏览器无报错；取消未完成试听不能评分，完成后可以保存。主分析平台入口已验证。
- 类型检查与 183 项源码测试通过；真实目录检查单独运行。旧 V3/V3.1 HTML 指纹部署前后一致。
- 音频线程观测不代表扬声器延迟或听感质量。动态 EQ 是否更符合偏好仍需用户试听。

## 复现

用 `scripts/build_v30_tuning_catalog.py` 将原 V3 目录与已绑定的声学证据合并；该脚本不会替换 V3 的窗口或原曲。音频、分析目录与试听偏好不提交到 GitHub。

在 web 目录运行：

```sh
npx tsc --noEmit
npx vitest run src --cache=false
V30_CORPUS=/path/to/prepared-corpus npx vitest run src/v30/corpus.test.ts --cache=false
npm run build:v30
```

独立静态目录使用构建后的 `v30.html` 作为 `index.html`，同时放置 catalog.json、catalog.json.gz、cases.json、v3-clock.js 和 assets。主分析平台只新增入口；不替换旧版本的 HTML 或脚本。
