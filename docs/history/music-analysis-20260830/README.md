# HarBeat 音乐分析历史工作总览

## 1. 本次冻结的目的

这份历史分支不是新的算法版本，而是把此前分散在代码、实验目录、报告和任务记录中的工作整理成可审计的团队基线。后续合作者应能回答：

- 哪些音乐量已经能稳定测量；
- 哪些高层特征仍只是候选；
- 69 项规则为什么不足以稳定区分 21 种风格；
- 已经做过哪些机器学习实验，数据是否泄漏，指标如何；
- 段落识别当前能做什么，下一步应训练什么；
- 哪些原始数据没有上传以及如何复现。

## 2. 三条历史主线

### 2.1 显式音乐特征

处理链以 Beat/Downbeat/Bar 和 Demucs 分轨为公共时间轴，进一步生成节奏、低频、打击乐、人声、和声和制作特征。工程上已经建立：

- 特征注册和语义层级；
- 模型路线状态；
- 版本化校准配置；
- held-out 指标门禁；
- unavailable/provisional/candidate/failed/validated 状态；
- 评测脚本和回归测试。

详细内容见 [01_传统69项特征.md](01_传统69项特征.md) 和原始 788 行说明 [HarBeat_音乐特征分析方法与验证结果_20260828.md](../../HarBeat_音乐特征分析方法与验证结果_20260828.md)。

### 2.2 风格机器学习

使用 65 首、13 类参考曲做了冻结 Discogs-EffNet 表示的原型实验。所有片段继承整曲和主艺人的 Fold，最终按整曲聚合评分。比较了：

- 单项技术特征；
- 65 项连续技术特征；
- Discogs-EffNet 1280 维嵌入；
- 技术特征与嵌入融合；
- 69 项显式特征手写规则。

最佳融合结果为 Top-1 80.00%、Macro-F1 0.796，但因为融合相对嵌入只增加 1.5 个百分点、数据纯度未完成人工复核、缺少 8 类和独立外部测试集，模型卡明确禁止接入运行时。

### 2.3 段落识别

现有分析链已接通 All-In-One：

- 能输出 Beat、Downbeat 和功能段落；
- 功能段落包含 start/end/raw label；
- 无模型结果时可回退到能量变化候选；
- 现有 phrase_map 仍是固定 8 小节加能量规则，不是真实语义段落。

目前的主要缺口是完整 sections 持久化、统一时间轴、人工边界/标签真值和正式指标。MERT/TCN/BiGRU 的结构修正网络尚未训练。

## 3. 当前结论的证据等级

| 结论 | 证据 | 能否用于生产承诺 |
|---|---|---|
| BPM/Beat/Downbeat 等底层能力有专项验证 | 独立公开数据集与版本化配置 | 只在报告声明的域和门控内 |
| 69 项规则不足以承担 13 类主分类 | 同一 65 首配对实验 | 可作为当前数据上的工程结论 |
| 嵌入路线显著优于显式规则 | 配对结果与 McNemar/Bootstrap | 可决定下一阶段研发方向 |
| 13 类融合达到 80% | 四折艺人隔离、整曲评价 | 仅原型指标，不能外推 21 类 |
| All-In-One 能跑出段落 | 单曲真实推理与工程测试 | 可作为候选生成器 |
| 段落标签准确 | 尚无人工真值 | 不能承诺 |

## 5. 不应被重新解释的历史事实

- “实现了一个特征”不等于“该特征已验证”。
- 事件检测模型通过，不等于事件关系或乐器身份自动通过。
- F1、Accuracy、容差内比例必须结合任务定义、样本不平衡和验证域阅读。
- 65 首切成 872 个片段仍然只有 65 个独立作品。
- 任何片段不得跨 Fold；同一主艺人不得跨 Fold。
- 文件名、艺人名、目录名和旧风格规则分数不得进入模型输入。
- 13 类结果不能外推到缺失的 8 类。
- 固定 8 小节 phrase_map 不得称为真实 Section。
