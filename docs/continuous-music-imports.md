# 实时播放器：音乐导入与下一首风格

入口：`https://8.136.120.255/listen/`。本次功能沿用现有实时渐进交接和人声重叠评分。

## 用户操作

- 在“接下来”选择“选下个风格”，选择已有标签，再点“按此风格选歌”。系统优先选择节奏兼容、最近没有播放的歌曲。开启自动续播会在当前策略的曲尾阶段尝试衔接；“现在接歌”可以提前请求交接。
- 风格偏好会继续用于后续推荐。手动选择具体歌曲时清除偏好；也可以点“取消偏好”。曲库的浏览筛选不会覆盖明确选择的下一首风格。
- 在曲库标题旁点“添加音乐”。使用现有分析平台的管理员账号登录；公众听歌无需登录。凭据仅在当前页面内存中使用，不写入本地存储。
- 本地上传支持 MP3、WAV、FLAC、M4A、AAC、OGG、Opus、AIFF。每首 20 秒至 20 分钟，最大 100 MB，每批最多 16 首。
- 歌单导入支持网易云、QQ 音乐公开歌单分享链接。先读取歌单，勾选歌曲，再匹配音源；可核对歌手、版本和音源后确认下载。放屁音乐和酷我沿用旧仓库的提供方实现；平台不可访问、无匹配音源或下载不完整时会报错，可以改用本地文件。
- 可给新歌选择一个现有风格标签。未指定时保留模型分析结果，暂不自动归入人工风格标签。
- 上传完成后关闭窗口不会取消后台任务。进度分为排队、下载、传输、Jetson 分析、准备衔接素材、可播放。失败可重试；相同文件和相同音源编号会去重。

## 部署与数据流

1. 云端 Nginx `/api/listen-import/` 对全部导入请求与任务查询使用既有 `/etc/nginx/harbeat-analysis.htpasswd` 认证，并代理至 `127.0.0.1:8771`。
2. `harbeat-listen-imports.service` 是独立服务，代码在 `/srv/harbeat-listen/import-service/code`，使用 `/srv/harbeat-listen/venv`。SQLite 队列位于 `/srv/harbeat-listen/imports/jobs.sqlite3`，仅一个后台 worker。队列容量 16，进程重启可恢复。
3. 音频先通过大小、时长、音频流检查，再按 SHA-256 去重，随后经既有私网 SSH 发送到 Jetson。
4. Jetson 在 `/home/mark/harbeat-listen-imports` 中启动独立的 user systemd 任务，调用已安装的 `harbeat-same-style-preprocess`。重用现有 GPU 环境，不替换 PyTorch 或模型。格式不符合渲染要求时，先统一音频，再对同一个文件进行全部分析。
5. 主分析、分轨和人声时间轴完成后，复用已有分析平台的序列化队列运行或核验 `dj_signals`、`genre`。同曲历史结果按源音频与分轨绑定复用。新文件的输入指纹、处理后主音频指纹和分析 run 保持可追溯。
6. 云端复用原有渲染配方：生成新歌可接入的窗口，也为既有歌曲补齐从新歌接入的窗口。同 BPM 的既有变速素材直接复用。逐首处理，避免一次载入整个曲库的详细分析。
7. 核验新音频指纹后发布到 `/listen/media/<sha256>.flac`。曲库使用版本化详情路径，完整检查后原子切换 `current`。现有播放会保留原音频；新曲发布后的页面刷新曲库不会重新启动播放器。

## 运行和回滚

- 配置文件：`deploy/listen-imports/harbeat-listen-imports.service`、`nginx.conf`、`requirements.txt`。
- 服务日志：`journalctl -u harbeat-listen-imports.service`。数据库 payload 与任务目录含私有源文件路径，不能放入公开静态目录。
- Jetson 任务名：`harbeat-listen-import-<job-id>`，状态与详细日志位于 `jobs/<job-id>/`。未授权用户无法通过导入 API 查询任务。
- 轻量导入曲库清单：`/srv/harbeat-listen/imports/inventory.json`，首次从原 `prepared-jobs.json` 流式迁移，不改变原清单。
- 播放器发布目录：`/srv/harbeat-listen/releases`。回滚时将 `current` 原子指向此前发布版本。旧版本详情和音频保留，供旧页面继续播放。发布和前端更新共用 `release.lock`，避免互相覆盖。
- 服务每次开始导入/生成素材前检查磁盘，保留约 5 GiB 空间。触发空间不足时保存已有分析并停止当前发布，不切换公开曲库。扩容后在界面重试。
- 定期将 SQLite、轻量清单和已发布版本元数据备份到 NAS/备份存储。新导入音频及中间结果会保留在 Jetson/NAS；清理前先确认已有可恢复备份。

## 当前边界

- 这是管理员管理共享曲库的入口，不是每位听众的私人账户/歌单系统。没有接入新的计费或多租户权限体系。
- 外部平台只对实际返回的可访问音源工作；搜索命中不保证下载成功，也不会将一个平台的歌曲编号当成另一个平台的编号重试。
- 分析结果未通过节拍、人声绑定或动态 EQ 质量检查时，新歌只标记为可单独播放，不伪装成可混音。
- 当前自动续播沿用已有曲尾触发策略。此前发现的“拖到最后数秒可能来不及接歌”未在本次导入/风格功能中修复，不能据此承诺任意操作下永不中断。
- 当前云服务器磁盘余量有限，大批量导入前需要扩容或迁移音频至对象存储。200 人容量方案是另外的基础设施执行计划，不代表当前实例已达到该容量。
