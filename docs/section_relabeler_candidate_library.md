# SongFormer 段落重命名：候选分类器库与盲测协议

更新日期：2026-09-02

## 结论先行

当前 65+8 首数据已经被充分拆成五层可独立验证的证据，但它仍只包含 36 首可训练的独立歌曲。段落虽然有 437 个，同一首歌内的段落高度相关，不能把它们当成 437 个独立样本随机拆分。因此本轮不直接宣布一个“最终模型”，而是冻结六个候选版本，等新的、从未参与开发的测试集到达后做一次统一比较。

现阶段最好的低风险开发集结果是 `c04_mixed_audio_v4`：按整首歌曲分组的交叉验证准确率为 85.81%，相对 SongFormer 的 83.30% 修正 11 个错误，没有改坏原来正确的标签。但这只是开发集结果，不等于未来歌曲上的最终准确率。

## 数据实际提供了什么

### 1. SongFormer 本段证据（52 维）

- 八个标签概率和对数概率；
- 上一段、下一段的标签概率；
- SongFormer 原始标签 one-hot；
- 段落时长、全歌相对位置、置信度、第一/最后一段等。

它回答的是“这一段自身看起来像什么”和“相邻段落是什么”。

### 2. 全歌结构关系（24 维）

- 本标签在全歌出现的比例和第几次出现；
- 与前后同标签段落的距离；
- 最近非相邻相似段落、相似段落数量；
- MusicFM 与 MuQ 多视角相似度；
- 前后是否都有重复、相邻与非相邻相似度差。

它回答的是“这一段在整首歌的重复结构中扮演什么角色”，覆盖了重复主 hook、出现次数、前后距离和全歌关系等信息。

### 3. 冻结音频编码器投影（1024 维）

MusicFM 与 MuQ 的全局/局部、原始/去中心化八个视图，每个视图固定随机投影为 128 维。投影种子和维度固定，训练与未来推理完全一致。

### 4. 混合音频 DSP（312 维）

在 SongFormer 已确定的段落边界内汇总 log-mel、MFCC、chroma、频谱对比度、响度、onset、频谱质心/带宽/rolloff/flatness 和过零率。它不修改边界，只增加音色、和声、节奏密度与能量证据。

### 5. Demucs 分轨证据（208 维）

对 vocals、drums、bass、other 四个 stem 汇总能量占比、onset、log-mel，并对人声增加 MFCC 与 chroma。它用于判断人声/鼓/低频配置的变化，不把某种乐器直接等同于某个结构标签。

五层特征都以 `(track_id, segment_index)` 对齐；本轮 437 个训练段落的覆盖率均为 100%。训练脚本遇到缺行、重复 key 或维度不符会直接失败，不会补错位置。

## 六个冻结版本

| 版本 | 输入层 | 维度 | 用途 |
|---|---|---:|---|
| `c01_songformer_local_v1` | 本段与相邻 SongFormer 信息 | 52 | 最小基线 |
| `c02_whole_song_structure_v2` | c01 + 全歌关系 | 76 | 验证结构关系的独立贡献 |
| `c03_encoder_projection_v3` | c02 + MusicFM/MuQ 投影 | 1100 | 当前生产候选的同类方案 |
| `c04_mixed_audio_v4` | c03 + 混合音频 DSP | 1412 | 验证音色/节奏/能量增益 |
| `c05_demucs_stems_v5` | c03 + Demucs 分轨 | 1308 | 验证人声与乐器配置增益 |
| `c06_audio_and_stems_v6` | 所有证据 | 1620 | 检查完整特征是否优于单一音频扩展 |

每个 JSON 模型均保存：完整特征名与顺序、均值/方差、分类器系数、阈值、训练歌曲 ID、数据集 SHA-256、特征矩阵 SHA-256、缓存 SHA-256、Python/NumPy/scikit-learn 版本以及参数 SHA-256。

## 防过拟合协议

1. 只使用 development 训练；结构混乱歌曲继续排除。
2. 所有折叠按 `track_id` 分组，绝不把同一首歌的段落分到训练和验证两边。
3. 主分组种子只用于选择正则强度和安全门槛；另用十个固定种子报告稳定范围。
4. 安全门控要求开发集上的覆盖达到最小数量且改名精度至少 90%；不满足时模型保持 SongFormer 原标签。
5. 六个版本全部保存，不根据当前开发集只保留“赢家”。
6. 历史 8 首 test 已在早期流程中暴露，不再用于本轮选择。
7. 新盲测集必须使用全新歌曲 ID；评估器发现与训练集 ID 重叠会拒绝运行。
8. 盲测结果文件默认不可覆盖，防止反复试验后只保留最好的一次。

## 新测试集到达后的操作

新数据必须继续使用 `harbeat_section_label_dataset_v1`，并保持每段的 `track_id + segment_index + start + end + SongFormer 概率 + annotation`。需要比较全特征版本时，还要先生成与新数据对应的结构上下文、混合音频缓存和 Demucs 缓存。

```bash
python3 scripts/evaluate_section_relabeler_candidates.py \
  --dataset /path/to/new_blind_annotations.json \
  --split test \
  --audio-cache /path/to/new_section_audio_context_v1.npz \
  --stem-cache /path/to/new_section_stem_context_v1.npz \
  --candidate-dir reports/section_relabeler_candidates_20260902 \
  --output /path/to/blind_result_once.json
```

评估器按同一测试集同时输出六个版本的安全门控结果、未门控分类器结果、逐段预测和统一排名。没有某类缓存时，对应候选会明确标记为 skipped，不会把缺失特征静默填零后参与排名。

## 当前数据边界

- verse：166 段 / 36 首；chorus：124 段 / 35 首，覆盖较好。
- pre-chorus：29 段 / 11 首，仍偏少。
- bridge：9 段 / 6 首；instrumental：15 段 / 8 首，不能仅凭段落数判断已学稳。
- SongFormer 置信度低于 0.60 时错误率为 37.25%，高于等于 0.95 时仍有 4.63% 错误，说明阈值必须与结构/音频证据联合使用。
- 全歌第三四分位中的第三分位错误率最高（26.32%），与“较长主歌后半段被命名为副歌”的现象一致；位置和重复关系确实是有效输入，但 36 首歌不足以证明某种固定序列规则能泛化到所有风格。

### 历史 8 首歌只作风险诊断

模型冻结后，评估脚本在已有 8 首 test 歌曲上做过一次连通性检查。这个集合曾被早期实验查看过，风格字段也只记录为 `input`，所以不能作为新的盲测集或用于继续调参。它仍揭示了重要风险：SongFormer 基线只有 59.29%；c03 为 60.18%，c04 为 61.06%，并且两者都改坏了 3 个原本正确的段落。也就是说，开发集上的“零伤害”没有在这 8 首分布不同的歌曲上保持。当前六个版本均不得直接升级为正式模型，必须等待新的、有代表性的盲测歌曲。

完整统计见 `reports/section_relabeler_candidates_20260902/dataset_audit.json`，每个候选的逐次交叉验证与修正明细见同目录 `reports/`。
