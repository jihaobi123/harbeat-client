# 给第二版后端负责人：仓库说明与实现手册

状态：**初步实施设计，待前端与 RK 接口评审；不是已经上线的第二版后端。** 核对日期：2026-09-13。源码基线：`94e38b7`；本次只读核对了 Jetson、NAS、阿里云，并在用户 Android 真机上查看了已安装的新 APK。

## 你负责的工作，用一句话说清楚

**你负责 Jetson 和手机 App 的服务端：管理歌曲及分析结果，让手机选歌，把所选歌曲的全部预处理信息和音轨可靠地交给指定 RK3588。**

你不写手机界面，不写 RK 下载客户端、实时混音、播放引擎，也不写戒指/手环姿态控制。你要与 RK 负责人约定下载任务、文件清单、状态回报；不能把“RK 来写客户端”理解成后端不用提供接口。

## 先看这张职责表

| 位置 | 执行什么 | 你要负责什么 |
|---|---|---|
| Jetson | 业务 API、数据库、预处理任务、已有模型 | 编写业务服务和任务管理；调用已有模型，不重训模型 |
| NAS | 原音频、分析 JSON、四轨、鼓子轨、人声时间报告 | 保护文件，建立可查询目录，提供受权限控制的读取 |
| 阿里云 | 公网 HTTPS 入口，经私网联系 Jetson | 与项目负责人核对并配置入口、证书、转发；不把混音搬到云上 |
| 手机 | 页面展示、用户选择、显示设备反馈 | 你提供接口；页面和联网权限由前端实现 |
| 手机热点 | RK 上网 | 它是网络接入，不是手机 App 代下载文件 |
| RK3588 | 领取任务、下载校验、本地混音播放 | RK 负责人实现；你提供资源及服务端任务状态 |
| 戒指/手环 | 姿态控制 RK | 不属于你的工作 |

## 今天就能运行的参考代码

[reference/read_delivery.py](reference/read_delivery.py) 是只读程序，读取 EDM 基础和人声索引，核对版本与 JSON，列出每首歌全部文件。不是后端服务，不带鉴权，不产生下载 URL，不运行模型，不写数据库或 NAS。

在仓库根目录执行，`--root` 填已经获准访问的 NAS 根目录或完整交付包解压根目录：

```bash
python docs/backend-v2/reference/read_delivery.py --root /mnt/nas/harbeat/preprocess
```

需要 `jsonschema`。请用独立后端开发环境安装，不要改 Jetson GPU Python 的 torch。要完整重新计算音频 SHA256，添加 `--verify-audio`；默认只核对音频存在及大小，并完整校验 JSON 指纹。旧 EDM ZIP 不含后加的人声报告，需把人声增补包按相同目录结构合并到解压根目录。

这个程序给你明确的起点：先能读现有交付物，再将相同逻辑接入目录服务。生产读取必须增加账号权限、并发控制、审计和文件不可被其他用户修改的保证。

## 还不能擅自决定的事项

- 新 APK 主要页面已实看，但源码、真实请求和登录方式未确认；当前准备页明确使用 Mock，不能声称前端已经按本文联网。
- 真机包含 Pad 预设同步。是否纳入本期后端“配置/音效的保存与下发”待负责人确认；触发执行和固定安全控制始终由 RK 负责。
- 第一阶段建议用独立测试账号、预分配设备凭据；正式用户/设备绑定方式须评审，禁止公网匿名访问。
- 旧数据库账号是否迁入新库、新库隔离方式、谁有权使用哪些歌曲须项目负责人确认。
- 157 首基础结果当前均为 degraded，不是损坏或全部不可用；是否允许特定质量标记的歌曲进入 RK 准备任务须确认。本手册建议测试环境显式允许，正式环境默认拒绝未经确认的 degraded 策略。
- 手机播放/暂停等控制是否经云端传递、设备支持哪些命令，由新前端和 RK 负责人共同确定。本期资源交付完成不得冒充已经实现播放控制。
- 阿里云旧网关有重启异常。不能因为看到服务名就停旧服务或覆盖 nginx，须先确定现有路由使用方。

**这些待确认项不阻止开发只读目录和模拟设备测试；会阻止生产迁移、公开下载和宣称全页面联调完成。**
