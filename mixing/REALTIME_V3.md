# V3 实时试听原型

入口：https://8.136.120.255/analysis-lab-static/v3-live-20260920/index.html

这版使用已有六首 Hip-Hop 的原音频、原始小节网格、SongFormer 段落、人声区间和局部能量曲线。播放期间点击下一首、提高／降低能量或 Trap／Grime，浏览器重新选择未来可执行的交接窗口，实时完成双轨播放、EQ 和淡化。原来的 V3 离线算法及试听文件保留。

## 试听

1. 点击“开始实时试听”。首次需要加载、校验并解码当前歌曲，后台准备候选素材。当前使用 FLAC，首次公网下载可能超过一次交接的等待预算；错过窗口时会提示重新选择，已下载素材继续复用。
2. 播放中选择下一首、能量或风格；也可以指定下一首歌曲。等待预算可设为 10、18、30 秒。
3. 查看计划中的 A 进出点、B 来源区间、变速比例、人声重叠和候选理由。若无符合目标且来得及执行的方案，当前歌曲继续播放，页面说明原因。
4. 交接开始前可以取消。交接锁定后，普通请求保留最新一条，完成当前交接再规划；停止始终可用。
5. 导出全部日志，核对计划与音频线程观察。暂停会暂停音频时钟，继续播放后沿原计划推进。

逐次触发的选点、评分和方案依据，见 [在线混音日志说明](REALTIME_LOGS.md)。

## 与离线 V3 的关系

保留 V3 的双轨增益 0.76、线性淡化、低频控制、交接窗口人声判断及 B 最后半小节恢复 EQ 的原则。A 低频 -9 dB、高频 -1.4 dB；B 低频 -7 dB、高频 +1.2 dB，满足双人声条件时中频 -5 dB。低频 140 Hz、高频 3600 Hz、中频 1200 Hz，Q=1.05。

在线选点改为未来原始小节边界与 2／4 小节进入窗口，不能再固定每首播放到第一遍副歌结束。目标、等待时间、变速幅度、人声风险和段落边界共同参与选择，分数属于待试听校准的规则。

浏览器使用 Web Audio Biquad、湿干混合与自有 5 ms 前瞻采样峰值限幅器，和原 FFmpeg 滤波、限幅实现不同；没有声称波形完全相同或完成原生手机验证。交接后 B 正文恢复原速；片段边界额外作 4 ms 平滑。

## 计算与素材

- 离线：校验音源／分析 SHA256、人声与运行版本绑定；准备每首前 150 秒原速素材，以及保调变速的单曲进入片段。
- 实时：筛选候选、判断人声重叠、安排播放时间、双轨 EQ／音量自动化、输出限幅及执行日志。
- 素材中没有预混好的转场或整场音频。本次共有 6 个原速素材、212 个变速进入素材，约 271 MB；浏览器按需下载，PCM 缓存上限 192 MB。
- 素材未就绪时不强行交接。下载后按原请求剩余预算重新规划，代次编号阻止已取消的异步请求重新启动播放。

## 代码与复现

- `scripts/build_realtime_assets.py`：素材及来源清单。
- `web/src/realtime/planner.ts`：纯规划与请求生命周期。
- `web/src/realtime/cache.ts`：哈希校验、解码和缓存。
- `web/src/realtime/transport.ts`：共享音频时钟与双轨执行。
- `web/public/v3-clock.js`：输出保护及音频线程观察。
- `web/src/realtime/RealtimeLab.tsx`：控制和计划／执行对照页面。

依赖 Python soundfile、FFmpeg，以及 web 的 npm 依赖。输入目录沿用 Hip-Hop V3 的 `listen/plan.json`、`inputs/inputs.json`、`inputs/reports/` 和原音频，音源不提交 Git。

```sh
python scripts/build_realtime_assets.py --data-dir /path/to/hiphop-v3 --output /path/to/live-assets
cd web
npm ci
npm test
npm run build:live
```

将 `web/dist-live/`、生成的 `catalog.json`、`asset-build.json` 和完整 `media/` 放在同一个独立静态目录，复制 `realtime.html` 为 `index.html`。需要 HTTPS 或 localhost 才能使用 AudioWorklet。当前部署由 Jetson 原分析服务提供静态文件，阿里云转发，没有替换生产主页面或重启服务。

## 验证与边界

94 项前端测试和 4 项素材测试通过，覆盖规划、取消、锁定、延迟准备、音频自动化及限幅器。真实六首素材已在桌面 Chromium 和窄屏布局执行播放、取消、暂停／继续、交接中追加请求，以及 Trap→Grime 的交接；检测到非零音频输出。72 个曲目／位置／意图组合中 65 个能在 18 秒内找到方案，其余返回具体原因。

“实际时间”表记录音频处理块到达计划帧的观察时间，不是扬声器输出测量。限幅器另有 5 ms 延迟，系统、声卡和蓝牙延迟未测。浏览器显示回调到达时间也不等于音频执行时间。

段落和小节尚未经人工逐首确认；模型风格仅覆盖这批曲目的 Trap／Grime。能量依据已有局部曲线，未完成跨曲感知校准。本版每首最多 150 秒、每首最多四个进入锚点；后台挂起、原生 App 音频中断、蓝牙和锁屏播放仍需原生引擎集成及真机验证。

公网复测也已通过：首次候选下载错过窗口，缓存就绪后重试完成交接；取消、交接中追加请求、暂停／继续正常，没有浏览器错误或 HTTP 失败。三个音频处理块观察偏差约为 2.13、2.24、1.32 ms。238 个发布文件完成 SHA256 校验，旧 Hip-Hop V3 页面仍返回 200。
